# U3 실사용 피드백 라운드 — 트리아지와 판정

접수 2026-08-25. S 로드맵 11항 완주(v0.4.0 출하) 후 두 번째 실사용 라운드다. 6건 전부
「문서 만들기」(job)·편집기(editor) 표면이고, 전건 코드 실동작 대조를 마친 뒤 설계 택일
4건은 사용자 확정(2026-08-25)을 받았다. 추적 부모는 **#873**, 슬라이스 번호 정본은 그
KICKOFF 코멘트다. 이 문서는 판정의 정본이고, 조치의 잔여는 이슈가 센다.

판정 요지: 6건 중 「존재하지 않는 결함」은 0건이다. 2건(§1·§4)은 명백한 구현 결함,
2건(§2·§3)은 의도된 설계의 UX 비용이 실측에서 기각된 것, 2건(§5·§6)은 영속 기본값의
부재다.

## 1. 저장 차단 알림이 write-only — 「⚠ 작업 이름을 입력하세요.」 잔존 (#874)

**현상** 편집기에서 한 번 뜬 차단 알림이 이름 입력·저장 성공·화면 재진입 어디서도
사라지지 않는다.

**원인** `saveMessage` 를 세우는 전이(`frontend/src/screens/editor.ts:824-826`)만 있고
`null` 로 되돌리는 전이가 저장소 전체에 없다. 타이핑은 `invalidField`(테두리)만 지우고,
저장 성공 경로는 통지를 쓰지 않으며, 컨트롤러가 부팅 시 1회 생성 싱글턴이라 화면 이탈로도
안 지워진다. 기존 테스트는 「세운 뒤 지워지는가」를 검증하지 않았다.

**판정** 결함 실재. 차단 사유가 해소되는 전이에서 알림을 지운다.

## 2. 프리셋이 임의 작업에 항상 뜬다 — 구조 호환 결속으로 (#875)

**현상** 다른 템플릿(TXT 작업 포함)에서 만든 프리셋이 전부 목록에 떠서 정보 노이즈다.
비호환 프리셋은 적용을 눌러 봐야 「0개를 적용했고 N개는 …」로 드러난다.

**원인** 프리셋 저장은 전역 단일 디렉터리이고 목록에 필터가 없다. 저장 시점 템플릿
식별자(`provenance.template_application_id`)가 기록은 되는데 소비처가 0이다 — 결속 정보가
있으면서 죽어 있다. 「Work 밖 재사용」은 명시적 설계였으나(#821 D1), 그 비용을 완화할
장치가 적용 후 사후 통지 한 줄뿐이라는 것이 실측 판정이다.

**사용자 확정** 결속 기준은 **구조 호환** — 프리셋의 `selection_set` 이 현재 템플릿의
선택지 구조에 전부 적용 가능한 것만 표시한다. 식별자 결속(재가져오기 시 고아화)과
비활성+사유 병기(노이즈 잔존)는 기각. 호환 판정은 적용 경로의 RESOLVED 판정과 같은 단일
출처를 쓴다 — 목록과 적용이 두 곳에서 따로 판정하지 않는다.

## 3. 「입력이 필요한 항목」 상시 노출 — 조치 필요만 표시 (#876)

**현상** 수정할 것이 없어도 구획이 항상 뜬다. 다른 구획들도 확인할 것 없는 상태에서 상시
렌더된다.

**원인** 이 목록은 이름과 달리 「수정 필요 목록」이 아니라 현재 활성 누름틀 전건의
분류표라(seal 성공 시 전부 「유지됨」), 빈 목록 조건만으로는 거의 절대 숨겨지지 않는다.
프런트도 라벨을 무조건 렌더한다(`frontend/src/screens/job_run.ts:999`).

**사용자 확정** **조치 필요(`action_required`) 항목만 표시**하고 0건이면 구획을 숨긴다.
다른 구획도 「확인할 것이 없으면 숨김」이 기본이되, 미지정=조치 요구 상태(저장 폴더 미지정
등)는 숨기지 않는다 — 숨김이 「묻고 확정하게 하거나 시끄럽게 알린다」를 삼키면 안 된다.
필터 판정은 링1/직렬화 층 소유, 프런트는 표시 항목 0건이면 구획을 세우지 않는다.

## 4. 옵션 왕복마다 재확정 — 판본 스코프가 선택 종속 (#877)

**현상** Option A/B 가 서로 다른 누름틀을 포함하면 옵션을 바꿀 때마다 수정 필요가 떠서
재확정해야 하고, A↔B 왕복 시 무한 반복된다.

**원인** 단일 지점: 매핑 커밋이 durable Field Binding 판본을 **커밋 시점 선택에서 활성인
필드로 필터**해 저장한다(`src/hwpxfiller/webapp/seal_execution_plan_service.py:452-453`).
A 확정 → 판본={A}. B 선택 → B 가 「새 활성 필드」 → 차단. B 확정 → A 규칙 탈락 → A
재선택 시 대칭 반복. `job.mapping` 에는 양쪽 값이 남아 정보 손실은 아니다.

**판정** 결함 실재. 한 번 확정한 규칙은 비활성이 되어도 판본에 남긴다(커밋 = 활성 필드
upsert + 비활성 규칙 보존). 「새 활성 필드」는 판본에 정말 없는 필드에만 선다. 왕복
시나리오(A 확정→B 확정→A 재선택 = 재확정 0건)를 헤드리스 테스트로 세운다.

## 5. 「수정…」 진입이 마운트 데이터를 못 받는다 (#878)

**현상** 데이터를 불러온 상태에서 「수정…」으로 편집기에 들어가면 데이터가 겨눠져 있지
않아 파일을 다시 불러와야 한다.

**원인** repair 진입이 편집기 세션을 `keep_data=False` 로 재구성하고, 데이터 앵커 승계
가드가 `document_browser_new_work` 전용이라 repair 를 배제한다
(`src/hwpxfiller/webapp/screen_editor.py:812-826`). JobController 의 마운트 데이터 자체는
왕복에서 살아 있다 — 편집기로 넘기는 인계 통로가 새 작업 전용 하나뿐인 배선 문제다.

**판정** 결함 실재. repair 진입에도 데이터 인계를 배선하고, 이탈 가드 확인 문안(「사라지는
것: … 데이터 …」)을 실동작에 맞춘다. §4 뒤에 착지한다(같은 흐름, 판본 스코프가 선행).

## 6. 영속 기본값의 부재 — 저장 폴더(#879)·마지막 데이터(#880)

**현상** 관리(hwpx) 작업은 저장 폴더 미지정 시 생성이 차단되고, 지정해도 세션이 끝나면
잊는다. 데이터도 매 세션 다시 골라야 한다.

**원인** 구식 축은 템플릿 옆 `Results` 자동 지정이 이미 있으나 관리 축은 폴백이 없고,
설정 층에 저장 폴더·마지막 데이터 키 자체가 없다. 앱 시작 자동 마운트 코드도 없다.
재료는 갖춰져 있다 — 세션이 데이터 성분(경로+시트+헤더행+풀키)을 한 벌로 포획하고, 로드
관문의 loud 거절·소실 배지 관용구가 이미 선다.

**사용자 확정** 저장 폴더 기본은 **템플릿 옆 Results**(구식 축과 일치). 마지막 명시 지정
폴더와 마지막 사용 데이터를 기억해 다음 세션 기본값으로 복원한다.

**판정** 신규 기능 2건. 복원 실패(폴더·파일 소실)는 조용히 빈 상태로 떨어지지 않고 기존
문구 체계로 사유를 재진술한다. 소실 판정 프로브는 화면 소유에서 공유 지점으로 올린다
(복제 시 표류). #879 → #880 순서(같은 설정 층).
