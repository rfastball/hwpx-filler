# React/TypeScript 전환 아키텍처 결정 기록 (ADR · R1)

> **문서 상태:** 유효 결정
> **권위 범위:** React 전환의 목표 구조와 계층별 권위 경계 — 무엇이 무엇을 소유하는가
> **후속 정본:** 단계 순서·상태 전이는 [R-00 헌장](https://github.com/rfastball/hwpx-filler/issues/394), 계측값과 검증 책임은 `react_ownership_inventory.toml`·`react_verification_ledger.toml`
> **편집 정책:** 결정이 바뀔 때만 갱신

이 문서는 R-00 헌장의 결정 원장(`R-D01`~`R-D17`)을 저장소 안의 **판단 기록**으로 옮긴다.
헌장이 *단계와 순서*를 정한다면 이 문서는 *왜 그 경계인지*와 *기존 결정 중 무엇이 승계되고
무엇이 대체되는지*를 남긴다.

**이 문서는 수치를 주장하지 않는다.** 계측값·집합·좌표는 전부 원장 2종이 소유하고 여기서는
항목 id 로 가리킨다(`inventory:<id>` — 소유권 인벤토리 · `ledger:<파일 경로>` — 검증 책임 원장).
원장의 값은 게이트가 저장소에 술어를 재실행해 지키므로, 값이 낡으면 게이트가 붉어지고 이 문서는
다시 쓸 필요가 없다. 이 규율은 1차 구현이 죽은 자리에서 나왔다 — 산문을 계약 표면으로 만들면
그것을 파싱하는 게이트가 자라고, 그 게이트가 결함의 주 생산자가 된다.

목표 구조는 헌장의 다이어그램이 정본이다. 요약하면 Python 이 제품 사실을 소유하고, 버전이 있는
공개 경계 하나가 그것을 프런트로 넘기며, 타입이 붙은 클라이언트를 지나 상태·selector 층을 거쳐
**단 하나의 React 트리**가 DOM 을 만든다.

## ADR-01 — 렌더 모델: 무엇이 대체되고 무엇이 남는가

**결정.** 화면을 그리는 권위는 Python 이 밀어 준 전체 스냅샷을 JS 가 서브트리째 재구성하는
모델에서, React 컴포넌트 트리가 소유하는 선언적 렌더로 옮긴다.

**이것은 [웹 재렌더 보존](WEB_RENDER_PRESERVATION.md)의 결정 본문을 대체한다.** 그 문서는
「전체 스냅샷 모델을 유지하고 부분 패치/vdom 으로 전환하지 않는다」를 닫았고, 그 결정이 오늘
뒤집힌다. 문서의 상태를 「부분 대체」로 옮긴 이유가 이것이다 — 근거가 낡아서가 아니라 **후속
결정이 결정 본문을 대체해서**다.

**뒤집은 것은 그 문서 자신의 재고경계가 아니다.** 그 문서는 「세 조건이 동시에 성립할 때만
다시 본다」는 트리거를 걸었는데, 오늘 그 세 조건이 동시에 성립하는 노드는 없다. 트리거는
발화하지 않았고, 강제함수는 상위 권위(R-00 헌장)의 결정이다. 이 구분을 흐리면 이 ADR 이
거짓을 적는 것이 된다.

**그렇다고 그 문서의 사실 진술이 오늘 참인 것도 아니다.** 첫째 근거(「푸시가 coarse 해서
타이핑 도중 재구성이 없다」)와 「현재 실효 범위」 절의 「재렌더되는 자유 입력 텍스트 필드가
없다」는 진술, 그리고 검증 절이 지목하는 게이트의 형상은 **오늘 거짓이다.** 셋 다 저장소가
그 문서를 쓴 뒤로 움직인 자리다. 여기서는 판정만 적는다 — 어느 줄이 어떻게 틀렸는지의 열거는
[PR-C 설계 패킷](https://github.com/rfastball/hwpx-filler/issues/401#issuecomment-5172281782)이
들고, 「어디까지 유효한가」의 영속 요약은 [문서 지도](README.md)의 결정 기록 표가 든다.

**잔존하는 것.** 절차성·북극성 정렬·엑싯 비용이라는 나머지 근거는 배경으로 유효하다. 특히
넷째 근거는 **예언**이었다 — 「보존 게이트의 단언은 패치로 가도 그대로 전이되므로 락인이
없다」. 그 예언의 진위는 검증 책임 원장이 되돌려 확인하게 한다. R2~R4 가 자산을 실제로
교체할 때 그 행의 후계가 무엇이 되는지가 답이다.

## ADR-02 — 권위 분리: 겹침도 공백도 허용하지 않는다

**결정.** 도메인·애플리케이션 사실과 거래 상태는 Python 이, DOM·표현·UI 수명주기는 React/TS 가,
창·WebView·운영체제 효과는 host 가 단독 소유한다. 같은 상태를 두 층이 판정하지 않는다.

이 저장소는 이미 링 경계로 같은 원칙을 지켜 왔고, 이 ADR 은 그것을 프런트 런타임 교체를
가로질러 이어 간다. 전환이 실제로 위험한 자리는 새 층이 생기는 곳이 아니라 **옛 층의 권위가
어디로 갔는지 아무도 안 적는 곳**이다. 그래서 R1 은 코드를 옮기기 전에 소유권을 먼저 셌다.

분류 어휘는 소유권 인벤토리의 `classification` 이 정본이고 다섯 값이다 — `react` ·
`python_product` · `host` · `retire` · `p_review_required`. 이 문서는 그 철자를 재진술할 뿐
새 어휘를 만들지 않는다. 오늘 점유자가 없는 값이 있어도 지우지 않는다: 「없다」와 「안 봤다」는
다르고, 그 구별은 원장이 데이터로 든다.

## ADR-03 — 공개 경계: 제품과 selftest 는 다른 문이다

**결정.** 제품 런타임이 쓰는 경계는 버전이 있는 `window.__hwpx` 하나다. selftest 는 명시적
capability 아래 `window.__hwpxTest` 만 쓴다. feature·component 코드는 두 전역도, 호스트가
심는 브리지 전역도 직접 읽지 않고 typed client 를 지난다.

경계를 하나로 좁히는 값은 **셀 수 있게 되는 것**이다. 오늘 인벤토리가 호스트 전역 참조와
브리지 참조를 각각 세고, 그중 문서 계약에 없는 도달 가능 표면을 판정 요구 항목으로 든다.
그런 항목이 조용히 늘지 않게 하는 것이 이 경계의 실제 효용이다.

## ADR-04 — 브리지는 객체째 주입한다

**결정.** 브리지는 전역에서 조회하지 않고 **객체 그 자체를 주입**한다. React 층의 typed client 와
store 가 들어와도 이 규율은 유지된다.

R2 이전에 이것을 헌장에 박는 이유는 순서 때문이다. 주입 규율은 나중에 되찾기가 가장 비싼
종류의 결정이다 — 전역 조회는 한 번 퍼지면 소비자마다 흩어져 자라고, 그때는 「어디서 읽는가」를
다시 세는 일부터 해야 한다.

## ADR-05 — 계약은 정본 하나, 도구는 나중에

**결정.** Python 과 TypeScript 가 같은 계약을 각각 손으로 유지하지 않는다. 한쪽이 정본이고
다른 쪽은 생성되거나 검증되며, 어긋나면 CI 에서 loud fail 한다. 생성 도구·router·전역 상태·
CSS 격리 방식은 **실제 문제와 경계가 확인되기 전에 채택하지 않는다.**

손으로 유지하는 목록의 실패는 가정이 아니다. 인벤토리의 판정 요구 항목이 그 실물이다 —
현행 대조 게이트가 **한 방향으로만** 보아 반대편에만 있는 이름을 구조적으로 못 보고, 같은
경계를 서술하는 머리말의 분해가 이미 낡았다. 둘 다 초록인 채로 틀려 있었다. 이 ADR 이 닫는
방향은 「문서를 더 자주 고치자」가 아니라 **양방향이 아니면 계약이 아니다**이다.

도구를 미루는 것은 결정 회피가 아니라 순서다. 도구는 경계가 정해진 뒤에 고르면 싸고, 먼저
고르면 경계가 도구를 따라간다.

## ADR-06 — React root 는 하나다

**결정.** 제품 화면은 하나의 컴포넌트 트리에서 생성된다. 전환 도중 불가피한 legacy host 는
**제거 책임자와 종료 단계를 가진 채로만** 존재하고, 신규 제품 기능을 받지 않는다. 장기 이중
앱·React island·런타임 선택 스위치·실패 시 Vanilla fallback 은 전부 닫힌 방향이다.

이 항목은 R1 에서 가장 자주 침식될 결정이다. 단계마다 「이번만 임시로」가 싸 보이기 때문이다.
그래서 임시 host 에 **종료 조건 없는 상태**를 허용하지 않는다 — 종료 조건이 없으면 그것은
임시가 아니라 두 번째 런타임이다.

## ADR-07 — 하나의 산출물이 세 소비자를 먹인다

**결정.** 정상 실행·selftest·패키징은 한 번의 clean 빌드가 낸 **같은** sealed 산출물을 쓴다.
출하 앱은 Node·개발 서버·외부 네트워크 없이 부팅한다.

이것은 새 결정이 아니라 선행 마일스톤이 이미 세운 계약의 승계다. React 가 들어오면 빌드 그래프가
바뀌므로 여기서 다시 못박는다 — 프런트 런타임을 바꾸는 일이 **산출물 동일성 계약을 흔드는
구실이 되지 않는다.**

## ADR-08 — 의미는 안 바뀐다

**결정.** R1~R4 는 사용자가 관찰할 수 있는 제품 동작과 Python 제품 계약을 보존한다. 의도적
UX 변경, 편집 엔진·렌더뷰 같은 기능 착지는 이 전환의 완료 조건이 아니라 **후속 소비자**다.

이 경계가 없으면 전환은 끝나지 않는다. 렌더러를 갈아 끼우는 김에 화면도 고치고 싶은 압력이
단계마다 오는데, 그것을 허용하면 「같은 동작인가」를 물을 기준면이 사라진다. 기준면이 사라지면
전환의 성공 여부를 판정할 수 없다.

## ADR-09 — 보존 책임은 이관되지 폐기되지 않는다

**결정.** 푸시가 화면을 다시 그릴 때 포커스·캐럿·스크롤 연속성을 지키는 **책임**은 React 층으로
그대로 넘어간다. 오늘 그 책임을 지는 얇은 옵트인 헬퍼는 사라져도 무방하지만, 그것이 지키던
사용자 관찰 가능 동작은 사라지면 안 된다.

[웹 재렌더 보존](WEB_RENDER_PRESERVATION.md)이 남긴 재고 술어의 **틀** — 어떤 조건이 겹칠 때
현 모델이 해로워지는가 — 도 폐기하지 않는다. 다만 그 틀은 문서 안의 산문으로 살지 않고 **노드
단위 술어**로 승계한다. 술어의 실물과 후계 게이트 지정은 검증 책임 원장이 진다. 이 문서는
승계한다는 사실만 적는다.

R1 은 그 후계를 **아직 지정하지 않는다.** 원장의 모든 행이 오늘 `keep` 인 이유가 이것이다 —
R1 은 아무것도 옮기지 않고 R2~R4 가 비교할 「before」 열만 고정한다.

## ADR-10 — 목표는 고정하되 배치는 박제하지 않는다

**결정.** 이 문서는 목표 구조와 권위 경계를 고정한다. 현재 파일 배치·모듈 분할·화면 구성은
영구 구조가 아니며, 단계별 작업 DAG 와 write set 은 **각 단계 진입 시점의 master 를 다시 측정해**
확정한다. 설계자·구현자·판정자는 역할과 컨텍스트를 분리한다.

R1 개방 자체가 선행 기반의 독립 판정을 조건으로 했다. 같은 규율이 아래로도 적용된다 — 단계의
완료를 그 단계를 만든 사람이 선언하지 않는다.

## ADR-11 — 어느 master 도 혼자 서야 한다

**결정.** 각 병합 시점의 master 는 실행·검증·revert 가능해야 한다. 여러 미완성 PR 을 동시에
합쳐야 정상화되는 방식은 금지한다.

R1 이 세 PR 로 갈린 것이 이 결정의 첫 회수다. 성격이 다른 산출물을 한 PR 에 실으면 되돌릴 단위가
사라지고, 그러면 「이 커밋만 되돌리면 된다」가 성립하지 않는다.

## ADR-12 — R 은 P 의 해법을 만들지 않는다

**결정.** React 전환 과정에서 드러난 Python 잔존 권위·화면 결합·host 경계는 **인계 후보로
기록**하고, 도메인·애플리케이션 내부 위치의 결정은 후속 P 단계가 소유한다. R1 은 그 항목을
`domain`·`application`·`port` 같은 형태로 세분하지 않는다.

인벤토리에서 `p_review_required` 로 분류된 항목이 그 인계 원장의 기준선이다. 각 항목은 현재
생산자·소비자·호출 경로·계약·테스트 증거를 함께 든다 — 다음 단계가 「이게 무엇이었는지」를
다시 발굴하지 않게 하려는 것이다.

---

## 이 단계가 답하지 않는 질문

아래는 **의도적으로 열어 둔** 것이다. R1 에서 답을 적으면 그것은 후속 단계의 실측을 선점하는
일이 된다.

- 어떤 router·전역 상태 라이브러리·CSS 격리 방식·타입 생성 도구를 쓰는가 (ADR-05)
- 화면을 어떤 컴포넌트로 자르고 그 경계를 무엇으로 정하는가
- 상태·구독·selector 의 물리적 층 구조
- 외부 편집·렌더 엔진 adapter 의 내부 형태
- Python 쪽 도메인·애플리케이션의 내부 재배치 (ADR-12)
- 오늘 시각 디자인 언어 문서가 적는 「순수 HTML/CSS」 진술의 정정 시점 — 그 진술은 **오늘 참**이라
  지금 고치면 반대 방향으로 거짓이 된다. 정정은 legacy 제거 단계가 소유한다

## 추적

이 문서의 결정 원장 표는 R-00 헌장의 `R-D` 항과 1:1 로 대응한다. 헌장의 항이 늘거나 이 표의
`R-D` 열이 그것을 덮지 못하면 R1 최종 감사가 `BLOCKED` 로 잡는다. 그 대조는 사람이 읽어 세는
체크리스트이지 새 게이트가 아니다 — ADR 을 다시 계약 표면으로 만들지 않기 위해서다.
