# 화면 규칙

<a id="ui-terms"></a>
## 용어·빈 값·단위

같은 개념은 버튼·오류·모달·로그·배지·파일 대화상자에서 같은 이름으로 말한다.
문안 정리만을 위해 Python/JSON 식별자나 문서에 남는 데이터 표식을 바꾸지 않는다.

| 개념 | 사용자에게 쓰는 말 |
|---|---|
| 제품 / `job` / `library` | 문서나르미 / 문서 만들기 / 문서 작업 |
| 매핑 원천 열 / 소스 종류 | 데이터 열 / 데이터 소스; '소스' 단독으로 열을 지칭하지 않음 |
| 저장 데이터 참조 / 통합문서 표 | 등록 데이터 / 시트; 구현의 '풀'은 노출하지 않음 |
| pclm SQLite 입력 | 계약 목록; DB의 뷰·표는 시트이며 이름을 그대로 보임 |
| 평문 토큰의 누름틀 전환 | 누름틀 변환 |
| 값 유형 | 텍스트 / 날짜 / 금액 / 고정값 / 오늘 날짜 |
| 날짜 표시형 | 시각 / 날짜+시각 등 표시형 명칭 |
| 칸 일부·글자 고치기(`text_slice`) | 가공; 방식은 문장(`‘x’ 앞까지`·`‘x’로 나눈 조각 중 첫째`·`‘x’ 대신 ‘y’`); 빠짐 처리는 원본 그대로 / 빈 값 |
| `Slot` / `Option` | 항목(저작) / 선택 |
| 저작에서 사용자가 범위·대상을 고르는 행위 | 고르다(`고른 범위`·`…고르세요`); 명사 '선택'은 `Option` 전용 |
| 원본 조치가 남음 / 조치 후 결과 | 템플릿 조치 필요 / 템플릿 변경사항 |
| 값 없음 / 의도적 미채움 | 빈 값 / 비움 확정, 선택지의 `(비움)` |
| 데이터 열 없음 / 연결 제안 없음 | 항목 없음 / 후보 없음 |
| 이름 붙인 필터 저장본 / 열 머리의 임시 조건 | 저장한 필터 / 열 조건 |

`{{#항목 <id> <라벨>}}`·`{{/항목}}`, `{{#선택 <id> <라벨>}}`·`{{/선택}}`은 저작 문법이며
데이터 열 용어와 다르다. 정확한 UI 문자열은 생산자·테스트가 소유하고 폐기 화면명을 되살리지 않는다.

본문 `MISSING_MARKER`와 미리보기 `〈빈 값〉`은 설명 문장이 아닌 데이터 표식이다.
연결 표는 생성 표식을 그대로 사용하며 표식의 '미입력'을 웹에서 '빈 값'으로 재조립하지 않는다.
사용자 설명에는 폐기한 '미입력'을 새로 추가하지 않는다.

위치는 `행`·`열`, 필드·파일·토큰은 `개`, 작업·결과 목록은 `건`을 쓴다.
수치·진행은 `선택 3/120`처럼 라벨로 표시한다. 시트 크기 추정은 `약 N행×M열`로
근사임을 밝히고 실제 로드 행 수와 혼동하지 않는다. 공유 파일 필터·작업 방식 라벨·식별 요약은
기존 생산자를 재사용한다. 폼은 React/CSS 라벨·필드 시작선을 맞춘다. Qt 레이아웃을 전제하지 않는다.

## 문안과 검수

문안은 문제와 다음 행동을 말한다. 정상 경로는 기본 무음이다. 화면이 이미 보여 주는 결과,
설계 이유, 하지 않은 일의 나열을 낭독하지 않는다. 실패·불확실성·손실은 숨기지 않는다.

| 문형 | 예산과 형식 |
|---|---|
| 버튼·메뉴 | 행동이 분명한 명사구·동사구 |
| 상시 힌트·부제 | 기본 0; 빈 상태에서 다음 행동이 필요하면 한 문장 |
| placeholder / 툴팁 | 입력 예·이름 한 구 / 한 문장 `이름: 설명` |
| 상태·수치 | 라벨; 정상 완료 낭독 없음 |
| 오류 | 최대 두 문장: 문제, 조치 |
| 파괴 확인 | 제목=행동, 본문=결과·손실 집합, 확인 버튼=그 행동 |

명령형은 `~하세요`, 취소는 `취소`, 파괴 버튼은 `삭제`·`덮어쓰고 생성`처럼 구체적인 동사다.
파괴 확인의 기본 포커스는 취소다. 손실은 `사라지는 것: 선택 3행 · 필터 2조건`처럼 쓰고
'계속하시겠습니까?'만으로 실제 손실을 숨기지 않는다.

문장 안의 긴 대시와 낫표는 마침표·쉼표·작은따옴표로 바꾼다. 테이블의 독립 빈 칸 표식은
문장이 아니므로 예외다. '결속하다·물리다·겨누다'는 사용자에게 '연결하다'로 풀어 쓴다.
미입력·빈칸·미매칭을 설명에서 혼용하지 않는다. 데이터 표식은 위 용어 절의 예외를 따른다.

`연결된 파일을 찾을 수 없습니다. 데이터 파일을 다시 선택하세요.`처럼 문제와 조치를 나눈다.
시트 선택 이유를 설명하되 '조용히 첫 시트를 쓰지 않습니다' 같은 설계 원칙 낭독은 붙이지 않는다.
이 예시가 실제 문자열의 두 번째 정본은 아니다. 주석·docstring은 사용자 문안 규칙 밖이다.
문안 정리로 JSON 키·판정을 바꾸지 않고 assertion·census를 같은 변경으로 갱신한다.

[ui-copy-census.toml](../tests/contracts/ui-copy-census.toml)은 문장 allowlist다.
[스캐너](../scripts/ui_copy_census.py)와 [검사](../tests/repo_contract/test_ui_copy_census.py)가
다중집합을 대조한다. 새 문장은 기본 0이며 필요한 전문·이유를 PR에 적고 등록한다.
열거 밖 문장은 추가하지 않는다. 지운 문장도 함께 제거한다.
`uv run python scripts/ui_copy_census.py --write`로 갱신한다.

'해야 …할 수 있습니다', 정상 완료의 '불러왔습니다·가져왔습니다·복원했습니다', 문장 뒤
수치 나열, '실제 …입니다', 현재 화면·모드의 낭독은 금지 패턴이다.
`legacy = true`는 기존 유예에만 쓰며 총수는 늘지 않는다. 새 문장을 면제하는 수단이 아니다.
실행 정의는 스캐너의 `NARRATION_PATTERNS`다.

문안 검수 절차는 셋이다. 변경이 더하거나 바꾼 사용자 문자열(단추·라벨·placeholder·접근 이름·툴팁·힌트·
오류·확인 본문)을 census 문장과 코드 변경에서 전부 열거한다. 문자열마다 문형·기능·검사 결과를 PR 본문
표로 적어 이 절과 용어 절에 대조하고, 남긴 예외에는 이유를 쓴다. 스캐너가 문장에 상투어 패턴을 건다.
상투어 정본: '손쉽게·간편하게·간단하게·편리하게·강력한·원활하게·최적화·스마트·직관적·완벽·효율적·
매끄러운·한눈에·지금 바로·걱정 없이·놀라운·혁신', 권유형 '~해 보세요', 문장 끝 느낌표와 이모지(상태 기호
⚠는 제외), '성공적으로·정상적으로', 해요체('~어요·~예요·~죠'). 문체는 '~하세요'와 '~습니다'만 쓴다.

## 시각·배치·접근성

데이터 표와 연결 확인을 우선하는 한국어 데스크톱 도구다. 콘텐츠 사이트·장식적 대시보드를
그대로 옮기지 않는다. 무채색 표면·얇은 경계로 구획을 나누고 액센트는 동작·활성·포커스에
절제한다. 미확인·누락·선택은 의미색과 라벨·형태·접근 가능한 이름을 함께 쓴다.

동급 구획의 밀도·시작선을 맞춘다. 제목·조작부와 중복되는 부제보다 빈 상태의 다음 행동과
실패 복구를 우선한다. 색·여백·모서리·타이포·모션·층의 수치는
[design_tokens.json](../src/hwpxfiller/viewmodel/design_tokens.json) →
[생성기](../scripts/gen_design_tokens.py) → [tokens.css](../frontend/css/tokens.css)가 소유한다.
값을 이 문서에 복제하지 않는다. 컴포넌트는 제품 CSS·React와
[갤러리](reference/ui-gallery.html), vendor 경계는 [아키텍처](architecture.md)가 소유한다. 데이터 하단의 시트 탭은 표와 경계·모서리를 잇고 활성 시트를 표면·굵기·밑줄로 구별한다. 단일 시트도 남기되 강조를 낮추며 가로 스크롤·키보드 초점·전체 이름 툴팁을 유지한다. 등록창은 파일/DB·이름·사용할 시트·메모 순서이며 체크 목록과 선택 수를 보여 준다. 선택 배경은 hover에서도 유지하고, 긴 목록과 본문은 스크롤하되 취소·등록은 창 안에 남긴다. 데이터 참조를 남기는 동사는 「등록」으로 통일한다.
메인 데이터 머리는 선택된 이름·보조 「변경…」·새로고침을 왼쪽 한 줄에 붙여 두며, 이름은 내용 폭만 쓰고 길 때만 줄인다. 변경·새로고침의 조작 높이를 맞추고 읽기 전용 입력칸을 두지 않는다.
미선택에서는 「데이터 선택…」를 강조하고, 연결 복구와 실패 사유는 별도로 보인다. 줄인 머리 높이는 표의 추가 행에 돌려준다.

TXT 검토·복사 작업대는 좁은 창·큰 글자에서도 제목과 본문을 읽을 수 있게 재배치한다. 진행 점은 높이를 제한하고
현재 항목이 바뀌면 그 점이 보이게 한다. 본문 조각에서 연결 행으로 가는 동작은 키보드로도 실행하며,
채운 모습·원문의 활성 상태와 초점 표지는 라이트·다크·강제 색상에서 구별한다.

튜토리얼은 상단 연습 표지·종료·과정 목록·대상 강조·안내 카드로 구성한다. 진행 표시는 현재 과정의 단계이며 전체 화면의 클릭을 막지 않는다.
화면별 다음 행동과 정확한 연습 사본을 안내하고 대상 부재·화면 밖 위치에는 복귀 행동을 제공한다. 관련 모달 안에서도 안내를 유지하며 대상 조작을 가리지 않는다.
완료 과정은 처음부터 안내로 진입한다. 일시정지 이유·재개는 연습 중에 보이며 종료 뒤 안내를 걷는다. 큰 글자·좁은 창·키보드·reduced motion과 기존 모달 초점·Escape를 유지한다.

저작 작업대는 문서 탭·구조와 필드 목록·편집면·속성·시험 결과를 구별한다. 의미 요소는 색뿐
아니라 이름과 경계선으로 표시하며 문서 모드는 표시만 걷는다. 예외로 원문의 문제 자리는 TXT·HWPX 모두 별도 층의 밑줄(오류 물결·경고
점선, 표지 위 Python 문장)이며 경보라 문서 모드에서도 선다. HWPX 편집기의 표지 상한을 넘으면 문제 표지부터 덜어 낸다.
캐럿이 선 구간 표기 줄의 짝 줄은 옅게 선다. 범위 확장·삭제·이름 변경은 적용
전에 실제 포함 내용과 연결 영향을 보여 주고, 미리보기가 서 있는 동안 편집면은 그 범위(넓힌 범위·대상·필드 사용 위치)를
강조하며 범위 강조에는 이름표를 달지 않는다. 전체 필드 이름 변경과 개별 사용 위치 변경을 섞지 않는다. 필드 전체 의미 해제는 모든 사용 위치를
한 번에 해제하는 전체 대상의 명령이다. HWPX 편집면의 기본 확대는 편집기의 「폭 맞춤」이며, 숫자 배율을 고르면 고정
배율로 돌아간다. 두 배율을 곱하지 않는다.
속성 폼의 확정은 Python이 준 확인 등급을 따른다. 영향이 없는 명령(none)은 제출 한 번에 적용하며, 만들기면 패널을
닫고 캐럿과 위치 줄을 새 요소로 옮긴다. 영향을 보일 명령(enter)은 첫 Enter가 영향을 세우고 입력이 그대로면 Enter 표기가 붙은
같은 주 단추(또는 다음 Enter)가 적용한다. 패널이 남는 이름 변경은 적용 뒤 카드·위치 줄·이름 칸이 Python이 되짚은 새 대상으로
서므로 제출은 다시 꺼진다. 파괴 명령(button)은 위험 단추로만 적용한다. 범위 확장·삭제·이름 변경은
늘 enter 이상이며 한글 조합 중 Enter는 어느 등급에서도 확정이 아니다. 만들기 명령으로 연 폼은 「명령」 선택 없이
명령 이름이 제출 단추이고, 이름 문법 거절은 그 입력 칸 바로 아래에 선다. 고른 문구 카드는 Python이 그 글자를 확정했을 때만 선다(빈 카드 없음).
필드로 만들기 폼의 「다른 같은 문구 찾기」는 폼 안 체크 목록을 세운다. 행은 모두 해제로 시작하고, 같은 문맥의 두 자리는 찾은
글자 강조와 흐린 위치 줄로 갈리며, 만들 수 없는 자리는 흐림과 Python 사유다. 체크한 자리는
한 명령이고 영향을 본 뒤 확정한다(enter).
단추는 역할이 곧 모양이다 — 구획마다 하나의 주 행동(채움), 보조(테두리), 물러선 행동(테두리 없음), 파괴(위험 채움),
그림 단추(이름은 접근 이름·툴팁). 원문으로 옮겨 가는 목록·트리 행, 브레드크럼, 메뉴 항목은 단추 모양을 쓰지 않는다.
상태 막대의 누를 수 있는 표지(문제 수·시험 상태)는 그 독 탭으로 가는 글 링크 모양이며, 해당 없는 상태는 상태 막대에 세우지 않는다.
머리 띠·도구 막대는 편집기처럼 명령을 테두리 없이 두고 띠마다 실행 행동 하나만 테두리·채움으로 세우며, 파일 동사는 「파일」 메뉴에 둔다.
위치 줄 끝의 메모 칸은 지금 자리에 대한 Python 사유 한 줄이며(되는 이름 변경이 없는 F2는 패널 대신 이 칸에 사유를 세운다)
다음 캐럿 이동이나 Escape에서 걷힌다. 캐럿이 문제 자리에 있으면 그 문제의 심각도 칩과 문장이 서고(겹침은 Python 판정),
그 자리를 떠나면 걷힌다. 도구 막대의 만들기 단추는 판정이 불가이면 흐린 `aria-disabled` 단추로 초점과
방향키 차례를 받고, 누르면 명령 대신 이 칸에 그 사유를 세운다. 판정 전에는 사유 없이 비활성이다.
구조 패널의 빈 상태 문장은 첫 행동인 필드 만들기 하나이며 필드도 항목도 없을 때만 선다. 처음 여는 문서에 첫 안내 알림은 없다.
문서 탭·도구 막대·구조 목록·메뉴는 WAI-ARIA APG 키보드 모델을 따라 한 번의 Tab으로 들어와 방향키로
옮긴다. 명령의 불가 항목은 표면마다 달리 싣는다. 자동 표면인 문맥 메뉴는 되는 명령과 대안만 싣는다. 판정 전에는
사유 없이 흐린 항목을, 되는 것이 없으면 팔레트를 여는 「명령」 한 줄과 그 위에 모든 불가 명령이 같이 가진 사유 한 줄을
싣는다. 유일한 예외로 편집면에서 연 문맥 메뉴는 「필드로 만들기」를 늘 첫 항목으로 싣고, 불가이면 흐리게 두고 Python
사유를 그 항목의 설명 줄로 보인다. 명시 표면인 명령 팔레트·속성 명령 선택·도구 막대는 불가 명령을 흐리게 두고 Python 사유를 보이며,
누른 키(F2)는 그 자리에서 사유를 보인다. 문맥 메뉴에서 불가 항목이 초점을 받아 사유를 읽히던 이전 규칙은 이것으로
대신한다. 편집면(TXT·HWPX)에서 비어 있지 않은 범위를 고르고 그 판정이 도착하면 선택 끝 줄 바로 아래에 되는 만들기와
대안만 기존 이름으로 싣는 작은 선택 옆 막대(이름 없는 group)가 선다. 끄는 동안에는 서지 않고, 초점을 옮기지 않으며
Tab 순서 밖이다(키보드 입구는 Shift+F10 문맥 메뉴). 선택이 바뀌거나 비면, 편집·스크롤·Escape·메뉴·팔레트에 걷힌다.
도구 막대(TXT·HWPX)의 「범위 고르기」는 만들기 무리 끝의 눌림 단추(`aria-pressed`)다. 켠 동안 편집면 누름은 캐럿을 옮기지 않고
자리만 정하며(캐럿 이동·키는 자리가 아니다) 위치 줄 메모가 시작 자리를, 시작을 받으면 끝 자리를 고르기가 끝날 때까지 청한다.
시작을 받으면 편집면은 시작부터 포인터 아래 자리까지(표 포함, 스크롤을 따라) 고무줄 범위를 이름표 없이 칠한다. 끝을 받으면 그
범위가 편집기 선택으로 서고 여느 선택처럼 선택 옆 막대가 따른다. 편집기가 스스로 세운 선택 뒤의 가운데 맞춤 스크롤은 막대를 걷지
않고 막대가 줄을 따른다. 키로 범위를 고르면(Shift+화살표) 그 범위가 서고 고르기는 접힌다. Escape는 고르기만 접고 단일 live
region이 취소를 한 번 읽는다. HWPX 편집면의 항목·선택 표지는 줄마다가 아니라 쪽마다 한 상자(본문 폭, 든 표·개체 포함)이며
쪽 경계에서 자른 변은 열어 두고, 선택 상자는 항목 상자 안에 들여 서며 이름표는 상자 윗변에 선다.
TXT 편집면은 표기 원문 대신 같은 어휘·색족의 이름표를 그린다. 필드는 이름에 필드 밑줄, 항목·선택의 여는 표기는 색 칩,
닫는 표기는 짝의 이름을 단 테두리 칩이고 범위는 줄 왼쪽 막대(항목 바깥·선택 안쪽)다. 템플릿 모드는 캐럿이 든 범위만,
이름표 모드는 모든 범위를 짙게 세우며 문서 모드는 색 없이 이름만 둔다. 이름과 짝은 Python이 정하고, 이름을 정할 수 없는
깨진 표기는 원문 그대로 보인다. 가린 표기는 한 덩어리라 캐럿이 그 안에 서지 않고 지우면 통째로 지워진다(실행 취소 한 번).
원문은 「원문 표기」 독에서 본다.
구조 목록의 항목 밖 사용 위치 묶음은 접힌 트리 줄(자식 줄은 펼친 뒤에만 짓는다)이며 심각도 칩은 든 필드 가운데 가장 무거운 것이다.
명령 팔레트(Ctrl+Shift+P, 「더보기」 메뉴에 키 표기)는 머리 띠 아래의 비모달 오버레이(APG combobox·listbox)다. 이름 부분 일치로 거르고,
되는 명령과 셸 동작을 단축키 표기와 함께 먼저, 불가 명령은 같은 사유끼리 한 번 묶어 뒤에 둔다. ↑↓는 흐린 항목에도
서고, Enter는 되는 항목만 실행하며, Escape는 팔레트만 닫고 연 자리로 돌린다.
초점은 사용자가 패널을 열 때만 옮기고 닫으면 연 자리(속성은 선택 자리)로 돌린다. 화면 읽기 알림은 단일 live
region이 상태 전이 때만 내며, 오류는 닫거나 같은 종류의 작업이 성공할 때까지 남는다. 오류 띠는 호출
실패만 보이고, 시험 입력 검증 실패는 시험 패널의 상태로만 보인다. 시험 입력의 공백은 결과 시험 탭 배지(시험을
시도한 뒤에만)와 입력칸 표지로 센다. 결과 시험 탭이 펼쳐지면 독은 더 큰 높이 몫을 받되 편집 몸통의 최소 높이(40vh)가 먼저다.
예외로 창 높이가 820px 이하이면 결과 시험 중에만 몸통 하한이 32vh로 내려간다. 결과 시험 패널은 상태 줄
아래의 결과 칸이 보이는 높이를 채우고(HWPX 결과는 맞춤 모드가 아닌 고정 배율로 연다), 보관한 시험 케이스(저장·가져오기·
내보내기 포함)·선택별 시험 상태·출력·제외 이유는 접힌 구획이다(케이스가 있으면 케이스 구획은 펼쳐 연다). 새 결과는
TXT·HWPX 모두 마지막으로 고친 시험 필드(없으면 고른 필드)의 첫 출력 자리로 결과 칸만 즉시 옮기며(한글 조합 중에는 옮기지
않는다), 결과 뷰어는 초점을 가져가지 않는다.

눌림 효과가 표 정렬을 깨뜨리지 않아야 한다. reduced-motion 두 경로의
[실렌더 기하](../tests/test_web_press_geometry.py)를 검사한다. 저작 작업대의 열 폭·좁은 폭 시트·
결과 시험 칸 높이·강제 색상 표지는 창 폭과 글자 배율별 [배치 실렌더](../tests/test_web_authoring_layout.py)가 잰다. 포커스·캐럿·스크롤·IME 연속성,
모달 포커스 포획·복귀와 비활성 사유를 지킨다. 라이트·다크 모두
[대비 검사](../tests/repo_contract/test_contrast_wcag.py)와 실제 렌더를 통과해야 한다.
대비 하한·대상 쌍은 테스트가 소유한다. [실앱 검사](../tests/test_web_selftest_gate.py)는
실제 결과를 검증하며 정적 CSS 존재나 테스트 통과를 접근성 인증으로 설명하지 않는다.
