# 작업 흐름

<a id="workflow-definition"></a>
## 작업 정의와 저장

| 개체 | 소유 | 혼동하지 않을 것 |
|---|---|---|
| 외부 원본 템플릿 | 최초 가져오기·명시 교체의 HWPX/TXT 입력 | 적용 후에도 추적할 파일 |
| 작업 `Job` | 템플릿 참조·연결·파일명 규칙·데이터 결속 | 데이터 행의 영구 사본 |
| 데이터 세션 | 읽은 행·선택·필터·범위·표시순서 | 작업 정의·등록 풀 원장 |
| 적용 판본 | 포획·검증·적용한 템플릿의 근거 | 계속 바뀌는 원본 경로 |
| 구성과 선택 | 적용 구조에서 사용할 항목·갈래 | 원본 저작·산출물 편집 |
| 실행 계획·봉인 | 검증 구성과 고정 입력의 실행 경계 | 이후 입력의 포괄 승인 |
| 배달 산출물·관찰 | 저장한 bytes·결과와 재읽은 관찰 | 실시간 미리보기·새 생성 |

편집기는 템플릿과 데이터를 같은 고르기 단계에서 조합한다. 풀의 조회 목록을 별도 원장으로
복제하지 않고 등록 데이터는 안정 `key`로 고른다. 경로·시트·헤더 행·종류를 한 벌로 포획하며
변경 가능한 풀 key에 열린 세션을 계속 매달지 않는다. 데이터 결속의 writer는 **편집기 저장 하나**다.
행 내용은 저장하지 않는다. 입력 미선택 세션에 저장 가능한 것처럼 보이는 우회 동선을 만들지 않는다.
새 저장본은 `binding_authority=job-mapping/v1`과 비활성분을 포함한 연결을 작업 JSON에 원자적으로 저장한다.
Binding은 저장된 연결에서 계산한다. 생성 잠금은 저장 검증부터 교체까지 유지하며 이후 확인 갱신 실패는 저장 성공과 구별한다.

연결 표는 필드·데이터 열·가공·표시형·미리보기의 다섯 축이다. 필드당 데이터 열은 하나이며 N→1
결합을 전제하지 않는다. 유형은 텍스트·날짜·금액·고정값·오늘 날짜다. 고정값과 오늘 날짜는 열을 읽지
않으며 오늘 날짜는 실행 시각을 쓴다. 추론에 따른 암묵 재서식은 하지 않는다.
날짜 기본은 시간 미포함이다. 시간 포함은 명시 선택하며 기존 `y2`·`kor`는 유지한다.
가공은 칸의 일부만 쓰거나 글자를 고치며 연결마다 하나다. 일부만 쓰기는 기준 글자 앞까지·뒤부터·사이, 구분자로 나눈 조각(번째, 음수는 끝에서),
앞에서·뒤에서 N글자, 글자 범위(시작·글자 수)이고 글자 고치기는 바꾸기·지우기다. 글자는 글자 그대로이며 기준 글자·나누기·고치기의 결과는 앞뒤 공백을 걷는다.
기준 글자·조각·범위가 없는 행은 빠짐 처리(`on_missing`)를 따른다. 편집 칸이 새로 짓는 가공은 원본 그대로(`keep`)를 싣고 키가 없는 저장 명세는 빈 값이며, 빠진 행은 미리보기에서 꼬리표와 「확인 필요」로 센다.
순서는 공백 정리 → 가공 → 표시형이고 고정값·오늘 날짜에는 없다. 고른 결과가 비면 빈 값과 같은 누락 표식이 선다.
유형·표시형·가공은 연결 판본(`field-binding/v5`)에 함께 실리고, 어느 생성 경로든 같은 해석기로
값을 렌더해 같은 글자를 쓴다. 모르는 표시형·가공은 원문으로 풀지 않고 거절한다. 표시형이나 가공을 다
싣지 못하던 이전 판본(`v2`·`v3`·`v4`)은 실행 입력이 되지 않는다. 구 저장본의 별도 Binding은 읽기만 하며,
현재 연결과 충돌하거나 이전 의미 판본이면 편집기에서 검토·저장해야 한다. 자동으로 한쪽을 채택하지 않는다. 오늘 날짜는 판본에
실행 시각 규칙(`RUNTIME_DATE`)으로 실린다. 규칙에는 날짜 표시형만 있고 열·고정값·가공·시각은 없다.
자동 연결은 제안이다. 일괄 확인은 제안 승격이지 미연결 전체의 비움 승인이 아니다.
유형·표시형은 `set_display`, 가공은 `set_slice` 한 전이로 바꾸며 backend가 명세를 판정한다. 가공 칸의 끌어 고르기 후보(`propose_slice`)·불러온 행 미리보기(`preview_slice`)도 backend 질의다.

미리보기는 선택 데이터의 값과 도메인의 생성 누락 표식을 그대로 투영한다. 웹에서 표식을
합성하지 않는다. 의도적 비움·값 없음·열 없음은 [화면 용어](ui-style.md#ui-terms)로 구별한다.
매 실행마다 연결을 다시 승인하는 흐름으로 설명하지 않는다.

탭 이동·이탈은 patch 정책을 거친다. `discard_patch`의 section이 있으면 그 부분만, 없으면
세션 전체가 되돌리기 범위다. 웹이 저장·버리기 결과를 먼저 선언하지 않는다. 이름 충돌은
저장 시 정확한 덮어쓰기 확인으로 다룬다. 저장 후 실행 진입도 데이터 결속을 확인하는 공용
명령을 쓰며 `select_job`만 부르거나 기억한 경로로 복원하는 지름길은 금지한다.

## 템플릿 저작·적용·구성

누름틀 변환·lint·스키마·구간 표기는 제품/커널의 결과를 쓴다. 변환은 명시적 사용자 행동이며 원본 변경과 산출물 생성을 구분한다.
TXT의 CodeMirror는 등록된 vendor 소유자만 설치·갱신·해제한다. 다른 프런트 모듈에서 vendor 객체·타입을 직접 소비하지 않는다.
TXT 장식은 분석 당시의 LF 본문(`source_text`)과 현재 본문이 같을 때만 갱신한다. 입력·한글 조합 중 늦은 분석에는 이동한 이름표·원자 범위를 유지하고, 표시 방식은 이동한 좌표에 적용한다.

템플릿 고르기의 편집 동사와 템플릿 만들기는 별도 저작 작업대를 연다. 문서마다 편집 이력·
선택·표시 모드·시험 입력을 보존하며 HWPX는 rhwp, TXT는 CodeMirror로 편집한다. 최근 작업 위치와
표시 모드는 앱 홈에 문서별로 두고 같은 bytes를 다시 열 때만 좌표를 복원한다. 구조·속성 패널 폭은
앱 전역으로 기억하며 글자 배율을 따라 자란다. 기록 이후 문서가
바뀌었으면 표시 모드만 복원하고 그 사실을 알리며, 읽을 수 없는 기록은 진단으로 보인다. 일반 문서로
연 파일의 첫 저장은 별도 경로를 고른다. 필드·항목·선택의 판정과 명령 미리보기는 Python이
소유하며 확정 직전 revision을 검사한다. 선택별 명령 가용 여부·사유·대안도 Python이 판정한다. 판정 전에는 사유 없이 비활성이다.
문서 명령 「원본 템플릿으로 되돌리기」는 선택이 아니라 문서 분석으로 판정하며 명령 팔레트에만 선다. HWPX 필드에 실제 값이
하나라도 있을 때만 되고 모든 값을 `{{이름}}` 원형으로 한 명령(한 번의 실행 취소)으로 되돌린다. 확인 등급은 button이고
저장한 뒤에는 지운 값을 되찾을 수 없다. TXT 필드에는 채운 값이 없어 늘 불가다. 채운 값은 템플릿 상태가 아니다(원문·부분 변환·변환됨).
표면별 불가 명령·사유 노출은 [화면 규칙](ui-style.md#ui-visual)을 따른다.
제안·보류는 Python 판정이며 만들기는 편집기 한 단위다. 「모두 필드로」는 제안만 만든다.
구조 목록·검색은 좌표 대신 대상으로 판정하며 편집기 선택의 되울림은 이를 덮지 않는다. 독에서 고르면 편집면 위치만 옮기고 독 탭은 유지한다.
속성 패널은 F2·문맥 메뉴·구조 목록·만들기로 연다. 「변경 영향·작업 적용」 탭은 Python이 연결 작업이
있거나 확인할 수 없다고 투영한 템플릿에만 선다. 구조는 문서 순서(항목→선택→사용 위치)와 이름별 필드 목록으로 본다.
소속·차례·문단/행 범위는 Python 투영이다. 항목 밖 연속 사용 위치는 수·문제 수를 담은 묶음으로 접고 현재 위치면 펼친다. 필터는 묶음 안도 찾는다.
HWPX 항목·선택은 본문 문단 단위다. 한 표 셀 안의 선택으로는 만들 수 없고(Python 사유) 필드 만들기는 그 셀 문단으로 판정한다.
표에 걸친 끌기는 편집기가 셀 쪽 끝을 그 표의 닻 본문 문단으로 접어(시작은 문단 머리, 끝은 문단 끝) 표 전체를 담은 본문
범위로 보고한다. 「범위 고르기」(TXT·HWPX)는 누른 시작·끝 자리 사이를 편집기 선택으로 세우며 HWPX 셀 안 누름은 같은 접기를 따르고,
편집·문서 전환·Escape·다시 누름에 접힌다. 속성 패널의 문맥 줄도 같은 범위 표시이며 원시 글자 좌표를 보이지 않는다.
검색 문맥은 앞뒤 본문·필드 표지만 보이고 명령은 원문 표기에만 둔다. 같은 문단·줄의 같은 문맥은 한 건이다. 시험 상태·준비·이름 변경·검색 요약은 Python이 짓는다.
이름 충돌과 하위 의미가 남는 해제는 구조화된 거절로 돌아오며 취소·다른 이름·기존 필드 연결·함께 해제의 해결 경로를 준다.
비었거나 문법 기호가 든 이름·식별자도 구조화된 거절(`invalid_name`)이며 해당 입력 칸을 가리킨다. 글자 범위의 필드 이름 제안(같은 문단 앞
「라벨:」에서만, 고른 문구 자체는 아니다)과 미리보기의 확인 등급(none·enter·button), 만든 요소의 위치도 Python이 짓는다. 한 의미 명령은 한 번의 실행 취소로 묶으며,
필드 전체 의미 해제도 모든 사용 위치를 한 명령으로 해제한다(한 자리라도 내용 보존을 확인할 수 없으면 전부 거절).
필드로 만들기의 `ranges`는 고른 자리를 포함해 글자가 같은 자리 전부를 한 명령으로 필드로 만든다(겹치면 거절). 같은 문구 자리(`same_text`)는 검색의 한 건 병합 없이 원시 자리이고 자리마다 필드 만들기 판정과 위치 줄을 Python이 싣는다.
정상 누름틀 뒤에도 필드를 이어 만들 수 있다. 기존 필드 겹침·위치가 불명인 제어요소 뒤는 거절한다.
문서·템플릿·이름표 표시는 원문과 변경 상태를 바꾸지 않는다. 문제는 템플릿의 결함(구조·호환성)과 저작 경고(공백만 다른
필드 이름, HWPX 본문에 평문으로 남은 필드 표기)이며 심각도·분류·대상·위치·다음 행동을 갖는다. 위치가 있는 문제는 문서
차례이고 위치 없는 호환성 경고는 끝이다. 평문 표기의 다음 행동은 그 표기 하나의 누름틀 변환이다. 상태 막대의 오류·경고 수는
문제 목록과 같다. 구조 오류가 있는 저장은 초안이며 사용 준비 완료와 구별하고, 저작 경고는 그 판정을 바꾸지 않는다.
시험 입력의 공백(손대지 않은 필드·선택 없는 항목)은 문제가 아니라 결과 시험의 상태로 센다.
HWPX는 편집 전 rhwp 왕복 결과를 Python에서 비교하며 그 보존 판정은 편집기 마운트와 무관하다. 판정 전에는
수정을 잠그고 확인 중으로 보이며, 마운트 실패도 판정 없음으로 기록해 읽기 전용 안내가 남는다.
보존을 확인하지 못한 문서는 이유와 함께 읽기 전용으로 열고 원본 bytes를 유지한다. 의미 복사는 세션 내부의 고정 사본을 쓰고,
붙여넣기 전에 기존 필드 연결·새 식별자·대상 범위를 확인한다.

시험은 현재 값·선택 구성의 결과만 보증한다. 값이 없거나 빈 필드는 생성과 같은 빈 값 표식으로 렌더하고
결과 보고에 알리며, 선택이 없는 항목은 시험을 거절한다. 원문이나 입력이 바뀌면 이전 결과는 오래된 상태이며
최신 성공 결과만 별도 내보내고 기본 파일 이름부터 시험 결과임을 밝힌다. 이름 붙인 시험 자료는 앱 홈에 명시적으로 보관하고 JSON으로
별도 가져오기·내보내기 한다. 템플릿 파일에는 시험값을 포함하지 않는다. 편집 중 초안은
따로 보관하지 않으며(편집기 자동 저장·복구도 끈다) 외부 파일 변경은 덮어쓰기 전에 비교·다시 열기·별도 저장으로 처리한다. 템플릿 저장은
기존 작업 적용이 아니다. 연결 영향 확인과 기존 변경 준비·적용 경계를 거쳐 명시적으로 적용한다.

적용 후 앱 홈 `template_authority/applied/`의 작업별 사본만 관리하며 외부 원본은 추적하지 않는다. 기존 작업도 저장된 적용본에서 복원한다.
교체는 명시적 가져오기·검증·적용으로 수행하며 적용본 손상은 거절한다.

항목·선택은 작성자가 제공하고 사용자가 고른다. 해석·깨짐·재검토는 backend가 판정한다.
`AUTO_KEEP`은 구조 fingerprint와 전체 내용 digest가 모두 같을 때만 가능하다. 본문 변경도 재검토 대상이다.

프리셋은 작업 밖의 선택 묶음이다. 전부 적용 가능한 항목과 손상 사유를 보인다. 저장·적용은 별개이며 자동 적용하지 않는다.
충돌은 반환된 기존 key로 확인하고 적용 후 새 token·view를 쓴다. 웹은 적용·깨짐 수치를 재계산하지 않는다.

'포함할 내용'의 노출·선택 필요·프리셋 호환성은 Python projection이 소유한다. blocker의 복구
동사에 도달할 수 있어야 하며 오류·거절이 구획 숨김 술어로 사라지지 않는다.
템플릿 변경 구획은 명시한 변경·초기화의 조치를 보여 준다. 외부 원본 변경·과거 준비 실패로 생성을 막지 않는다.
규칙 변경은 안내만 하며 실제 미연결이 없으면 별도 재확인을 요구하지 않는다.

<a id="workflow-data"></a>
## 데이터 세션·선택·범위

작업 선택은 결속 데이터를 열고, 데이터 선택은 그 데이터에 결속된 작업만 제안한다. 스키마는 필수 열 소실을 잡는 실행 게이트이며 대체 후보 기준이 아니다.
첫 후보 작업은 자동 선택하지 않고 마운트 직후 선택 행은 0건이다. 같은 데이터의 작업 전환은 재읽기·선택·필터 초기화를 피한다.
다른 데이터와 결속이 어긋나면 작업을 해제하며 결속 정보가 없으면 편집기로 연결한다.

엑셀·계약 목록 등록은 사용할 시트를 체크해 등록 항목 하나에 선언한다. 엑셀 파일 가져오기도 선택한 시트를 모두 읽을 수 있는지 확인한 뒤 한 항목으로 등록하고 첫 시트만 연다. 실패하면 일부만 등록하지 않고 사유와 선택을 남긴다.
같은 종류·경로·기본 시트의 기존 등록은 재사용하며 이름·메모·시트 선언 변경은 현재 등록을 재진술해 확인한다. 기존 단일 시트 등록도 유지한다. 보관 항목은 활성화를 요구한다.
데이터 표 아래에는(편집기 연결 확인 포함) 현재 등록이 선언한 시트만 탭으로 두며 전환은 등록 키를 유지하고 그 시트만 연다. 활성 세션은 하나이며 탭마다 편집·선택·스크롤을 보관하지 않는다. 새로고침과 부팅 복원은 마지막으로 연 시트를 유지한다.
시트 순서는 앱 홈의 등록 데이터 `opts.sheets`에 저장하며 기본 시트·현재 데이터·행 선택·필터는 보존한다.
전환은 기존 생성 잠금·결속 해제·선택 초기화 규칙을 따르고 실패하면 현재 데이터를 유지한다. 작업 선택과 교차 실행하지 않으며 연속 탭 누름은 대기 중 마지막 대상으로 직렬 전환한다.
연습·검증 외 기동은 등록 계약목록의 업무 설정에서 `.pclm`을 찾아 통합·접수·공고·계약 시트를 등록한다. 기억 데이터를 우선 복원하고 없으면 통합을 연다. 설정·자료 신원·필수 시트 확인 실패는 알리며 별도 DB 불러오기 버튼은 없다.

`JobDataSession`은 마운트·선택·필터·범위, `ActiveWorkSession`은 작업 identity·후보·재읽기·재연결·탐색,
`JobExecutionSession`은 구성·봉인·관찰·준비, `DocumentRunCoordinator`는 잠금·취소·입력 고정·덮어쓰기·결과·배달을 소유한다. `JobController`가 브리지를 조정한다.

`JobController`는 상태 잠금 하나로 dispatch·초기 당김·브리지·다른 화면의 직접 진입을 직렬화한다(생성 중단 요청과 입력을 고정한 뒤의 배달 구간만 잠금 밖). snapshot은 시작 때 한 번 포획한 활성 작업만 읽는 준비된 view의 순수 성형이며 IO는 `refresh_panel()` 같은 명시 경계에 둔다.
브리지는 `mounted_data_descriptor`·`owned_session_paths`로 필요한 설명과 경로만 읽는다.
편집기 handoff는 포획한 참조를 넘기고 풀을 다시 조회하지 않는다.

검색·열 필터·행 선택·범위 초안은 같은 세션을 겨눈다. 늦은 변이가 다른 데이터·닫힌 초안에
적용되지 않게 epoch를 대조한다. 숨긴 열도 필터·검색·생성에는 참여한다.
「+ 필터」 빌더는 지금 열 조건으로 채워 열리고 열 머리 편집기와 같은 엄격 검증으로 조건을 이름 붙인 칩으로 저장한다. 켜진 칩은 검색 OR 그룹처럼 한 필터 모델 안의 무리다.
같은 열을 보는 저장 필터끼리는 「또는」, 다른 열과는 「그리고」, 열 머리 조건은 「그리고」이며 정의줄은 열 무리마다 이름을 「또는」으로 잇는다.
칩이 조이는 열도 열 머리 표지를 세우고 그 열의 머리 편집은 칩을 끄지 않는다. 「열 조건」 칩은 머리 조건만이고 「모두 보기」는 칩까지 푼다.
정의는 등록 데이터 항목에 시트별로 붙는다(기본 시트 `filters`, 다른 시트 `sheet_filters`). 직접 연 파일·계약 목록도 같은 정체성의 등록을 쓴다. 여러 등록이 같은 비기본 시트를 선언하면 임의로 하나를 고르지 않는다.
계약 목록 db와 미등록 파일에는 저장하지 않는다. 세션 이송은 켜진 이름뿐이다. 없는 열·맞지 않는 범위를 가리키는 칩은 사유와 함께 켜지 않는다. 같은 이름은 덮어쓰지 않는다.
실행 입력은 선택 행을 표시순서로 투영한 고정 사본이다. index를 뒤늦게 해석하거나 표시순서와
원본 순서를 섞지 않는다. 작업대도 같은 사본을 받는다.

<a id="workflow-generation"></a>
## 생성과 덮어쓰기

HWPX 생성 경로는 하나다. slot 유무와 무관하게 작업 권위가 선 HWPX 작업은 현재 작업·결속 데이터·
연결·선택·적용본·준비를 검증하고 계획을 봉인한 뒤 materialization과 배달로 진행한다. 권위가 서지 않은
작업(초기 등록 거절)은 생성하지 않는다. CLI도 같은 경로를 탄다: 실행마다 임시 작업공간에 작업을 세워
초기 등록·저장된 연결의 해석·봉인을 거치고 끝나면 버린다. 파일 이름 토큰은 연결된 템플릿 필드의 값으로 푼다.
이전 검사, 활성 버튼, 유효 token 하나가 현재 실행 가능성의 증명은 아니다.
구성 변경·프리셋·경로 변경과 생성의 상호배제, 재전송 판정은 backend가 소유한다.

생성 요청은 실행 준비를 자동 갱신하고 검증 통과 후 생성한다. 별도 확인·미리보기 승인은 없다.
입력·무결성·지원 실패는 사유와 함께 거절하고 생성 뒤 결과를 관찰한다. 기존 파일은 `generate`의 `needs_overwrite` 확인을
거친다. 확인 대상과 실행 대상이 달라졌으면 이전 승인을 재사용하지 않는다.
배달 준비는 저장 폴더 관찰에 묶이므로 폴더를 바꾸거나 런이 실행되면 버리고 다음 실행에서 다시 관찰한다.
그래서 같은 작업을 다시 만들면 앞서 만든 파일이 덮어쓰기 확인으로 온다.
배달 준비가 캡처한 시각 하나가 파일 이름의 날짜 토큰, 이름 속 오늘 날짜 필드, 문서 본문의 오늘 날짜를
모두 정한다. 레코드 준비나 실행 진입이 읽은 시계로 따로 렌더하지 않는다.
파일 이름은 이름 kernel([output_name.py](../src/hwpxfiller/domain/output_name.py)) 한 곳이 해석·조립·판정하며
「문서」 열·편집기 예시·배달·CLI가 같은 함수를 쓴다. 닫히지 않은 `{{`는 규칙 오류이고, 폴더 밖·drive·ADS·
금지문자·끝 점/공백·Windows 예약 장치 이름(`CON`·`NUL`·`COM1` 등)은 쓰지 않고 거절한다. 배치 안 충돌과
기존 파일 충돌은 같은 대소문자 무관 규칙으로 판정한다. 진행 델타는 시작(0/N)과
레코드마다 보내며, 전건 안착한 런만 작업의 최근 실행 시각과 검토 기준선(그 런이 고정한 규칙)을 기록한다.
새 작업은 템플릿 권위가 선 뒤 저장된 연결을 바로 실행 입력으로 해석한다. 최초 Binding 채택이나
생성 중 연결 저장은 없다. 저장된 결정이 없는 활성 필드·깨진 연결은 편집기에서 검토·저장한다.
생성 직전 관찰이 복구가 필요한 실패면 생성은 예외가 아니라 그 사유를 담은 거절이다.
문서는 전건 materialization이 통과한 뒤에만 배달한다. 그래서 배달 전 취소나 레코드 하나의 실패는
파일 0건이다. 배달은 항목마다 원자적으로 쓰고, 쓰기가 실패하면 그 항목에서 멈추며 앞서 쓴 문서는 남긴다.
배달한 문서는 다시 읽어 기록 digest와 대조한다. 배달 결과(완료·중단)는 저장 폴더의 `fill-ledger-*.json`
사이드카(`managed-delivery/v1`)에 축적한다. CLI는 `--ledger`를 줄 때만 같은 원장을 남기고 데이터 출처 포인터를 더한다. 취소·일부 성공·배달 실패를 숨기거나 전부 성공/실패로 뭉개지 않는다. 화면에 별도
실행 원장을 만들지 않는다. 출력 위치는 [저장 규칙](#workflow-storage)을 따른다.

무엇을 바꾸면 어떤 준비 상태를 버리는가(모두 `screen_job.py`·`job_execution_session.py`·
`document_run_coordinator.py`):

| 바뀐 것 | 버리는 것 | 근거 |
| --- | --- | --- |
| 데이터 마운트·리로드 | 준비(record/delivery preparation) + 실행 결과 | `_invalidate_data_results` → `execution.invalidate_preparations` + `runs.invalidate_data_results` |
| 저장 폴더 변경 | 배달 준비만(레코드 준비는 유지) | `execution.invalidate_delivery` |
| 작업 전환·해제 | 실행 결과(마지막 생성·배달) | `runs.invalidate_work_results` |
| 템플릿 재결속·재연결 | 봉인·계획·준비 전체 | `execution.invalidate`(orchestration 리셋 + `invalidate_preparations`) |
| 템플릿 변경 적용(편집기 확정) | 봉인·계획·준비 전체 + 자동 재확인 | `execution.invalidate` + `_maybe_auto_check` |

결속·이름 패턴 변경은 위 표의 "템플릿 재결속" 또는 "데이터 마운트" 경로로 흡수된다.

BOOKMARK 진단(`structural_boundary.py`)은 표 셀·캡션을 지원하며 `BOOKMARK_CROSSING`을 보고하고 계속한다.
저작·materialization의 `bookmark_region.py`는 최상위 문단만 지원하고 짝이 native ctrl/run 형태가 아니면 `ValueError`로 멈춘다.

<a id="workflow-results"></a>
## 결과 관찰과 TXT 복사

HWPX '내용 보기'는 배달 파일을 재읽고 기록 digest와 비교한 뒤 재파싱한다. 세션 ordinal로
대상을 특정하며 파일명·표시 index를 권위로 쓰지 않는다. 파일 없음·digest 불일치·재파싱 실패·
세션 밖 대상은 각각 명시적인 실패다. 다른 이름으로 저장해도 검증해 관찰한 bytes를 쓴다.

관찰한 bytes는 저작면의 rhwp로 보기 전용 렌더링한다(편집·저장 없음). 원료 거절·
렌더링 실패는 텍스트 대체 없이 실패로 보인다. 입력·작업이 바뀌면 이전 결과는 과거 실행의
증거이지 현재 성공의 보증이 아니다. 현재성·과거 상태·실패·취소·배달 결과를 구별한다.

TXT 작업대는 진입 때 고정 사본(이후 선택과 무관)을 한 건씩 검토·복사한다.
클립보드 실패와 복사 진행을 구별하고 미연결·빈 값·비워 둠 표식을 유지하되 추가 확인 없이 복사한다. 연결은 읽기만 하고
「연결 편집」·「템플릿 편집」에서 고친다. 본문은 그 행 복사본의 임시 편집이고 보이는 글자가
복사된다(봉인 대조는 편집 전). 편집·진행은 나가면 가드 뒤 버린다.

<a id="workflow-storage"></a>
## 라이브러리·폴더·설정

라이브러리는 작업 찾기·선택·복제·삭제·복원을 소유한다. 상세 패널은 템플릿·데이터·연결을
설명하고 편집·생성으로 연결한다. 열린 세션 identity의 이름 변경은 그 세션 소유자가 처리한다.
손상 작업·끊긴 참조는 숨기지 않고 이유와 복구 동사를 제공한다. 태그·그룹은
[비노출 범위](product.md#product-scope)다. 표시 이름과 풀의 안정 key를 혼동하지 않는다.

앱 홈은 `HWPXFILLER_HOME` 또는 `~/.hwpxfiller`이며 [locations.py](../src/hwpxfiller/host/locations.py)가
해석한다. 레지스트리·설정·원장은 external/domain 소유자를 통해 접근하며 UI가 임의 경로로
우회하지 않는다. 풀은 행 사본 저장소가 아니라 참조다. 명시 로드·새로고침과 기동 시 기억 데이터·등록 계약목록 복원으로 세션을 만든다.
테스트의 autouse 앱 홈 격리를 끄지 않는다.

튜토리얼은 HWPX·TXT 생성, 데이터 교체·빈 칸 확인, 저작·변경 적용의 여덟 과정이다. 과정마다 독립 진입하고 연습 자원의 확인된 결과만 진행을 올린다.
공고서 연습은 계약담당자·전화번호·팩스번호를 고정값으로 연결하고 게시일과 입찰 일시의 표시형을 구별한다.
저작은 목록의 연습 서식을, 변경 적용은 작업의 내부 사본을 연다. 옛 T0–T17 기록은 과정 완료로 옮기지 않는다. 새 사용자에게만 첫 초대를 한 번 보이고 시작 전에는 예제를 설치하지 않는다.
연습 시작·과정 전환·종료는 실행 중 작업과 미저장 변경을 확인한다. 연습은 같은 창을 `tutorial_workspace/`의
과정별 홈으로 전환해 사용자 서식·작업·풀·설정에 쓰지 않는다. 시작·처음부터는 그 과정의 전제를 새 홈에 깐다.
종료는 사용자 환경과 떠난 화면(못 열면 라이브러리)으로 돌아가고 전환 실패는 재시도할 수 있게 남긴다. 비정상 종료 뒤에는 사용자 환경으로 기동한다.
일시정지·건너뛰기·앱 종료는 연습 위치와 홈을 보존하고 재시작에는 안내를 자동 재개하지 않는다.
연습 파일 정리는 이전 버전이 사용자 서식 폴더에 남긴 사본만 다룬다. 영향 확인 뒤 작업·등록 데이터가 참조하거나 수정된 파일과 결과를 보존하고, 읽을 수 없는 작업·등록 데이터가 있으면 중단한다. 삭제 실패는 알리고 지웠거나 없는 사본의 기록만 뺀다. 학습 기록 전체 초기화는 별도 확인이며 일반 앱 설정 초기화와 섞지 않는다.

출력 위치는 설정 모달의 전역 `last_output_directory` 하나다. 편집기·작업 화면은 공용 해석
결과를 읽기 전용으로 보여 준다. 유효 설정 폴더, 템플릿 옆 `Results` 순서로 해석하며 둘 다
불가하면 `OUTPUT_DIRECTORY_REQUIRED`로 막는다. 순수 판정은
[output_folder_default.py](../src/hwpxfiller/domain/output_folder_default.py), 투영은
[output_folder_zone.py](../src/hwpxfiller/webapp/output_folder_zone.py)가 맡는다.

템플릿 풀은 가져올 서식을 찾는 사용자 폴더다. 작업의 앱 소유 적용본과 별개이며 누름틀 변환은 제자리에서 한다.
사용자 폴더용 앱 휴지통은 없다. 명시 루트가 사라졌으면
출력 폴더와 달리 임의 fallback 없이 실패를 알린다. 루트 소속은 경로 해석기로 판정하고
문자열 prefix로 인정하지 않는다. 폴더 교체·재연결은 관련 세션을 갱신한다.
[template_root.py](../src/hwpxfiller/external/template_root.py)와
[template_root_default.py](../src/hwpxfiller/domain/template_root_default.py)가 원천이다.

설정은 테마·글자 크기·폴더·튜토리얼 버튼 표시를 제공한다. 생성 중에는 관련 폴더 변경만 이유와 함께
잠근다. 공유 FolderRow와 기존 설정 경계를 사용한다.
화면 좌표 변경은 [live101](../scripts/live101/scenario.py)·selftest·실렌더와 함께 검증한다.
헤드리스 `tests/test_webapp_*.py`와 [프런트 테스트](../tests/js),
[실앱 검사](../tests/test_web_selftest_gate.py)를 정적 계약의 대리인 없이 함께 사용한다.
