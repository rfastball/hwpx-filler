# 문서 유지 규칙

## 한 사실은 한 곳에

코드·테스트·빌드 설정은 동작의 최종 권위다. 문서는 현재 책임과 이유를 설명한다.
`docs/manifest.toml`이 문서의 경로·종류·역할·검토 입력·길이 예산을 소유하고, 문서 지도는
거기서 생성한다. 런타임 버전·공개 메서드·액션·CI job도 코드에서 생성한다.
현재 문서에서 과거 기록의 판정이 우선한다고 독자를 다른 원장으로 보내지 않는다.

| 종류 | 담는 것 | 편집 기준 |
|---|---|---|
| current | 현재 계약·사용 절차·규칙 | 코드/테스트 변경과 함께 재검토 |
| generated | 설정·AST에서 읽은 참조와 문서 지도 | 생성기만 작성 |
| machine | ring·coverage·문안 같은 기계 원장 | 소유 계약 테스트와 함께 변경 |
| evidence | 재현에 필요한 고유 형식 관측 | 관측 환경·한계를 보존; 현재 동작의 대리인 아님 |
| research | 아직 채택되지 않은 이론·제안 | 현재 구현과 구분; 채택분만 current로 옮김 |

완료 보고·피드백 회차·폐기 목업·이관 대조표는 Git 이력이 보존한다. 현재 규칙을 먼저
흡수하고 참조를 정리한 뒤 작업 트리에서 삭제한다. 기계 원장, 행동 테스트, 원관측 fixture,
현재 사용 중인 브랜드 자산은 역사처럼 보인다는 이유로 삭제하지 않는다.

## 자동 생성과 사람 검토는 다른 명령

```powershell
uv run python scripts/docs_contract.py --write
uv run python scripts/docs_contract.py --check
uv run python scripts/docs_contract.py --review docs/ui/execution.md
uv run python scripts/docs_contract.py --check
```

`--write`는 생성 참조와 문서 지도만 갱신한다. **검토 해시는 바꾸지 않는다.**
`--check`가 `review required`를 내면 해당 문서를 코드·테스트와 대조하고 필요한 내용을
수정한 뒤 그 문서 하나에 `--review`를 실행한다. PR에는 의미 변화 또는 설명 불변의 이유를
적는다. `--review`는 현재 입력과 본문 해시를 기록할 뿐, 내용을 자동으로 읽고 보증하지 않는다.

검토 입력은 파일 내용과 경로를 함께 해시한다. 파일 삭제·개명과 glob의 빈 매칭도 실패한다.
텍스트 줄끝은 정규화해 Windows/Linux checkout 차이가 허위 실패를 만들지 않는다.
검토 범위가 너무 넓어 무관한 변경마다 서명하게 되면 source glob을 더 구체적으로 분리한다.
검토가 번거롭다는 이유로 입력을 삭제하지 않는다.

## CI가 실패시키는 것

문서 누락·미등록 파일·중복 역할, 끊어진 로컬 링크/앵커, 생성 참조 불일치,
검토 입력·본문 변경 후 미확인, 비어 있는 source glob, 문서별 길이 예산 초과를 검사한다.
문서의 근거 테스트는 실제 존재해야 한다. 현재 문서에는 검토 입력과 근거 테스트가 필요하다.
외부 링크의 네트워크 생존 여부는 오프라인 게이트의 보증 범위가 아니다.

[문서 계약 테스트](../tests/repo_contract/test_documentation_contract.py)는 정상 저장소뿐 아니라
버전·브리지 변경, 잘못된 문서 등록, 링크 파손, 입력 변경 등 의도적 파손도 검증한다.
기존 `static` → `quality-gate` 경로에서 실행한다. 저장소 ruleset의 필수 status check도
`quality-gate`를 요구해야 병합 차단이 완성된다.

## 한계

해시와 링크가 맞아도 사람이 문장을 잘못 해석하거나 거짓으로 고칠 수 있다.
이 장치는 **탐지 가능한 구조·코드 드리프트를 강제**하고, 자연어의 의미 정확성은 관련
행동 테스트와 리뷰가 맡는다. 날짜만 새로 찍기, 모든 변경에 문서 한 줄을 강제하기,
모든 검토 해시를 일괄 재생성하는 명령으로 이 차이를 숨기지 않는다.

문서 추가는 먼저 역할을 정한다. 기존 문서와 같은 사실을 소유하면 분리 대신 통합한다.
길이 예산은 늘리기 전에 역사·중복·생성 가능한 목록을 제거한다. 예산·검토 입력 변경도
계약 변경이므로 PR에서 그 필요성을 검토한다.
