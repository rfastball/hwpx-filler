이 장면이 실물화하는 판정

  • 질문은 하나다 — '어느 템플릿을 어느 데이터에?'. 시트·헤더 행은 데이터 항목이 이미 들고 있고(durable 결속의 정체성 축), 파일 찾아보기로 새로 열 때만 시트 확정 게이트가 선다.
  • 템플릿 관리 동사는 항목의 ⋯ 메뉴로 물러난다 — 누름틀·구간 변환, 전부 표기로 되돌리기, 구간 항목 이름 바꾸기, 폴더에서 보기. 변환 전 항목은 숨기지 않고 비활성 + 사유다 (데이터 쪽 '끊김' 과 같은 문법 — §4 「사라진 파일」).
  • 연결 카드가 첫 미리보기다 — '자동 연결 10 · 확인 필요 2' 를 여기서 보면 2단계로 갈 이유가 사용자 눈에 보인다.
  • 지켜지는 계약: 결속 쓰기는 편집기 저장 하나(U4 §2.4) — 고르기 단계는 편집기 안이다. 표시명은 확장자를 뗀 것이고 하위 폴더는 상대 경로로 병기한다(확정 ⑤). 변환은 제자리 멱등이라 파일 하나가 항목 하나다(재판정 ②). 드래그는 가속기이고 클릭이 같은 결과를 낸다(확정 ④ · n8n 드래그 참조 결함의 교훈).

이 장면이 실물화하는 판정

  • 명시성 게이트는 지킨다 — '제안 → 확인' 전이는 여전히 사람이 만든다. 한 행씩 체크하는 대신 '제안 n건 모두 확인' 한 번으로 승격하고, 확인 필요 항목은 그 버튼이 건드리지 않는다. F-06 의 규칙 지문 두 축(source/format)은 그대로 산다.
  • 미리보기는 표 안에 산다 — 리서치의 가장 강한 신호다. 빈 값은 표식 〘미입력·…〙(제품 상수 domain/job.py MISSING_MARKER)으로 그 자리에 보인다. 조용한 빈칸을 만들지 않는다.
  • '사용할 데이터 열' 칩 구획은 퇴역한다(확정 ③) — 매핑되지 않은 열은 자연히 쓰이지 않으며, 표 바닥의 '사용하지 않는 데이터 열 6개' 한 줄이 그 정보를 잇는다. 링1 의 열 선별 상태·액션·저장 필드는 소비자 0 이 되는 시점에 함께 걷는다.
  • 7열이 4열로: '확정' 체크는 데이터 열 칸의 상태 배지로, '타입/고정값' 은 데이터 열 select 의 마지막 항목군(고정값…, 오늘 날짜)으로, '상태' 는 미리보기 셀의 표식으로 흡수된다.

  • 기본값의 구분자 — 여기 쓰인 — 는 문장 안 em-dash 가 아니라 두 이름을 잇는 이름 구분자라 COPY_STYLE_GUIDE §3-1 의 금지 대상이 아니다. 다만 구현에서 가운뎃점을 고르면 공고서 · 2026 하반기 계약 이고, 이 시안은 둘 다 허용으로 본다(확정 필요 없음).
  • 저장 폴더는 여기서 바꾸지 않는다 — #968 로 전역화됐다. 읽기 전용 재진술 + 설정으로 가는 길 하나만 둔다(같은 상태를 두 곳이 판정하지 않는다).
  • TXT 형식에는 문서 파일 이름 행이 서지 않는다 — 지금도 '파일 이름' 탭 자체가 없다. 그 경우 이 단계는 작업 이름 한 행 + 저장 폴더 재진술이다.

이 장면이 실물화하는 판정

  • 패널이 답하는 질문이 생긴다 — '이 작업은 무엇을 무엇으로 채워 어떤 파일을 만드나'. 지금 3행은 재료만 말하고 결과를 말하지 않는다.
  • '첫 행' 열은 데이터 파일을 읽어야 채워진다 — 선택 직후에는 — 로 두고 읽기가 끝나면 채우며, 끊김이면 그 자리에 사유를 쓴다(조용한 빈칸 금지). 나머지는 저장된 작업만으로 그려진다. 표의 — 는 빈 칸 마커 단독이라 COPY_STYLE_GUIDE §3-1 예외다.
  • 동사는 늘지 않는다 — '템플릿 재선택…' · '데이터 재선택…' 은 #966 의 deep-link 그대로이고, 하단 동사 5개는 현행 screens/library.ts 와 같다. 표의 행 클릭이 같은 배관으로 2단계에 착지한다.
  • 좁은 호스트에서는 연결 카드가 세로로 선다 — 편집기의 가로 3열을 그대로 눕히면 이름이 배지와 겹치고 부제가 말줄임된다. 같은 링1 투영, 다른 배치다. 표는 12행 중 8행을 프레임 안에 두고 나머지 4행을 이름으로 명시한다(스크롤로 조용히 감추지 않는다). 좌 목록:우 상세 비율도 1fr : 1.25fr 로 뒤집혀, 이 뒤집기가 U6-F 의 library.css 변경에 함께 든다.
  • 기각한 대안: 패널을 접어 목록을 넓히기 — 빈 공간은 정보 부족의 증상이지 레이아웃의 결함이 아니다. 접으면 증상만 가린다.
