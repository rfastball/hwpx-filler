# 핵심 워크플로

이 문서는 현재 제품의 개체·책임·전이를 설명한다. 이전 버전의 합의문이나 변경 이력보다
이 문서와 [현재 UI 계약](UI_CONTRACT.md)을 먼저 읽는다. 미래 표현 모델은
[표현 권위 계층 연구](DOCUMENT_AUTHORITY_LAYERS.md)이며 현재 구현의 보증이 아니다.

## 개체와 권위

| 개체 | 소유하는 것 | 다른 개체로 간주하면 안 되는 것 |
|---|---|---|
| 원본 템플릿 | 작성자가 관리하는 HWPX/TXT 원본 | 이미 적용·검토된 판본 |
| 작업 `Job` | 템플릿 참조, 연결, 파일명 규칙, 데이터 결속 | 데이터 행의 영구 사본 |
| 데이터 세션 | 읽어 들인 행, 선택·필터·범위, 표시순서 | 작업 정의·등록 풀 원장 |
| 템플릿 권위·적용 판본 | 포획·검증·적용한 템플릿의 근거 | 계속 바뀌는 원본 경로 |
| 구성과 선택 | 적용된 구조에서 사용할 항목·갈래 | 원본 저작이나 산출물 편집 |
| 실행 계획·봉인 | 검증된 구성과 고정 입력의 실행 경계 | 이후 입력에 대한 포괄적 승인 |
| 배달 산출물 | 실제 생성해 저장한 bytes와 실행 결과 | 현재 템플릿의 실시간 미리보기 |
| 산출물 관찰 | 저장한 실물을 재읽어 확인한 결과 | 새 materialization |

## 작업 정의

템플릿과 데이터를 골라 필드 연결을 확인한 뒤 작업을 저장한다. 데이터 참조는 경로·시트·
헤더 행·종류의 한 벌이며 **편집기 저장**만 그 결속을 쓴다. 자동 제안은 확정과 다르고,
명시적 비움은 누락과 다르다. 사용자에게 보이지 않는 암묵 재서식·추측은 하지 않는다.

필드 하나는 데이터 열 하나와 값 유형으로 구성한다. 고정값·오늘 날짜는 열을 읽지 않는
유형이다. N→1 열 결합이나 실행 때마다 매핑을 다시 승인하는 흐름으로 설명하지 않는다.
상세는 [작업 편집](ui/editor.md)이 소유한다.

## 원본 변경과 적용

원본 경로가 가리키는 현재 bytes와 이미 적용된 판본을 구분한다. 변경사항 확인은 후보를
준비하고, 적용은 검증된 후보를 권위 있는 판본으로 승격하는 명시적 전이다.
조회·렌더가 durable 상태를 새로 쓰는 write-on-read를 만들지 않는다.

원본이 변경됐거나 읽을 수 없어 현재성을 확인하지 못하면 실행 경계에서 알린다.
`unknown`을 `unchanged`로 취급하지 않는다. 최초 준비 실패의 부분 상태와 발급 identity는
그 호출의 소유 범위에서 정리한다. 이전부터 있던 유효한 권위까지 되돌리지 않는다.

## 구성과 선택

HWPX/TXT의 항목·선택 구조에서 작성자가 제공한 갈래를 사용자가 고른다. 원본 저작과
구성 투영을 분리하고, projection이 semantic authority를 대신하지 않는다.
선택의 해석·깨짐·재검토 필요 여부는 backend가 판정한다.

선택 자동 유지(`AUTO_KEEP`)는 구조 fingerprint와 적용 후보의 전체 내용 digest가 모두
동일한 경우로 제한된다. 관계없어 보이는 본문 수정도 현재 정책에서는 재검토를 요구할 수
있다. 영역별로 더 똑똑하게 판단한다고 설명하지 않는다.

프리셋은 작업 밖에 보관하는 선택 묶음이다. 적용 시 현재 구조에 다시 맞춰 판단하고,
저장·적용·확인 왕복은 같은 구성 mutation 규율과 생성 잠금을 따른다.

## 실행

현재 작업과 결속 데이터가 일치하고, 연결·선택·원본·준비 게이트를 통과해야 한다.
선택 행은 표시순서의 고정 사본으로 계획에 들어간다. 이전 검사 결과, UI 버튼 활성화,
유효한 token 하나만으로 현재 실행 가능성을 추론하지 않는다.

materialization과 파일 배달은 구분한다. 덮어쓰기는 확인한 정확한 대상에 한정하고,
취소·일부 성공·배달 실패를 숨기지 않는다. 실행 중 상호배제와 재전송의 판정은 backend에
있다. 화면은 응답을 표시할 뿐 독립적인 실행 원장을 만들지 않는다.

## 관찰과 재사용

HWPX 산출물은 배달 파일을 재읽고 digest를 확인한 뒤 구조를 관찰한다. 페이지 조판의
완전한 재현을 약속하지 않는다. 다른 이름으로 저장해도 관찰한 bytes를 유지한다.
입력·작업이 바뀌면 이전 결과는 과거의 실행 증거이며 현재 입력의 성공 보증이 아니다.

TXT 검토·복사는 진입 때 받은 고정 사본을 사용한다. 일시 편집과 복사 진행을 durable
작업 정의와 섞지 않는다. 상세 동선·소유자는 [실행과 결과](ui/execution.md)가 소유한다.

## 불변식의 실행 가능한 근거

의미 판정은 [domain](../src/hwpxfiller/domain)과
[application](../src/hwpxfiller/application), IO 효과는 external/host 경계에 있다.
[저장소 계약 테스트](../tests/repo_contract)는 의존·공개 경계·잠금·실행 provenance를,
[제품 행동 테스트](../tests)는 전이·거절·결과를 검증한다.
한 개의 승인 token이나 스냅샷을 이 모든 검사의 대리인으로 삼지 않는 것이 핵심이다.
