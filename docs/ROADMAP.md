# 발전 방향

이 문서는 장기 방향과 재개 조건만 소유한다. 진행 중·완료·담당자·마일스톤·일정은
[GitHub 이슈](https://github.com/rfastball/hwpx-filler/issues)가 소유한다.
열린 이슈 목록이나 완료 보고를 여기에 복제하지 않는다.

## 제품 경계

핵심은 재사용 가능한 작업으로 명시적인 값 치환과 사용자가 선택한 구성을 실행하는 것이다.
이름·값을 추론해 몰래 변환하거나 반복 표처럼 보인다는 이유로 구조를 바꾸지 않는다.
현재 지원과 비노출 범위는 [지원 경계](FEATURE_SCOPE.md), 현재 동작은
[핵심 워크플로](core-workflow.md)가 소유한다.

## 재개 조건이 필요한 방향

| 방향 | 착수 전에 필요한 근거 |
|---|---|
| HWPX 반복 행·라인아이템 | 실제 문서 수요, 부모/하위 레코드 데이터 모델, 병합 셀·행 좌표·ID 재작성의 격리 실험과 한글 round-trip 증거 |
| TXT 가변 반복 행 | 실제 수요와 라인아이템 데이터 형태 |
| 값 표본을 활용한 유형 추천 | 실사용 오추천 사례와 회귀 fixture; 제안과 자동 적용의 분리 |
| PDF 내보내기 | 실제 수요, 조판 엔진·변환기 선택, 설치·배포·실패 처리 경계 |
| ERP 연동 | 확정된 인증·엔드포인트·응답 스키마와 테스트 가능한 fixture |
| 여러 레코드의 단일 문서 병합 | N파일 흐름으로 해결되지 않는 수요와 제품 범위 재결정 |

이 조건은 기능 구현 약속이나 착수 순서가 아니다. 조건이 바뀌면 방향을 갱신하고 실제
작업은 이슈로 옮긴다. 이미 끝난 UI 이관, 리뷰 라운드, 삭제한 문서의 복원 방법을
「다음 착수 후보」에 남기지 않는다.

## 연구와 현재 계약

[문서 표현 권위 계층](DOCUMENT_AUTHORITY_LAYERS.md)은 미래 모델을 검토하기 위한 연구다.
그 이론의 모든 계층이 현재 제품에 구현됐다고 가정하지 않는다. 원본·구성·산출물의 현재
책임은 워크플로와 코드로 확인한다. 채택할 변경은 현재 계약과 행동 테스트에 반영한 후에만
제품 동작으로 설명한다.
