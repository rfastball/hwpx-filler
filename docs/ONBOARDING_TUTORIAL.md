# 온보딩 튜토리얼 — 동봉 예제 세트와 진행 감지 체크리스트

> **문서 상태:** 유효 결정
> **권위 범위:** 배포본 동봉 예제 세트(#284 승계)와 앱 내 튜토리얼 안내의 설계 —
> 자산 명세·루프 커리큘럼(기본/응용/고급 + 선택 심화 티어)·순간 카드·단계 판정·설치/제거 경로·슬라이스 분할
> **후속 정본:** 없음(구현이 착지하면 표면 계약은 [UI 계약](UI_CONTRACT.md)이 소유한다)
> **편집 정책:** 결정이 바뀔 때만 갱신. 이산 조치는 슬라이스 이슈가 소유한다

## 0. 목적 — 한 시나리오, 두 독자

같은 시나리오가 두 독자를 섬긴다.

1. **최초 사용자**: 설치본(exe)을 받은 사람이 저장소 없이, 앱 안에서만, 15분에
   첫 문서를 만들고(기본 티어), 이어지는 티어로 자기 서식 템플릿화(고급)와 구간
   구성(선택 심화)까지 닿는다. 지금은 이 경로가 없다 —
   `examples/quickstart-101/` 은 저장소 체크아웃 + `uv` 전제라 exe 사용자에게 닿지
   않는다(#284 배경).
2. **제작자**: 이 시나리오를 실앱에서 완주하는 것이 UX 검증 루프다. 체크리스트가
   넘어가지 않는 지점 = 사용자가 막히는 지점이고, live 게이트가 같은 여정을 CI 에서
   반복해 튜토리얼↔앱 드리프트를 잡는다.

튜토리얼은 별도 모드나 연습 환경이 아니다 — **실제 앱, 실제 홈, 실제 생성 경로**를
그대로 쓴다. 가짜 환경에서 배운 것이 실전과 어긋나는 문제를 원천 배제한다.

## 1. 결정

### D1. 주입 방식 = 빈 상태 제안 + 명시 버튼 (#284 결정 ① 유지)

최초 부팅 자동 설치는 사용자 홈 무단 쓰기라 confirm-or-alarm 원칙과 어긋난다.
템플릿 라이브러리가 빈 상태일 때 「예제로 시작하기」를 제안하고, 편집기 「템플릿」
자리에 상시 진입점을 둔다. 누르기 전에는 홈에 아무것도 쓰지 않는다. 앱 내 표면이라
설치형·포터블·소스 실행이 대칭이다.

### D2. 예제 도메인 = 조달 실문서 각색 (#284 결정 ② 뒤집음)

#284 발안 때는 "특정 도메인 결합 회피 → 범용 중립 시안 신작"으로 확정했으나
뒤집는다. 근거:

- 실사용자군(공공기관·조달 실무자)에게 "내 일이 이 앱으로 된다"를 첫 15분에
  보여주는 것이 중립 시안보다 강하다. 범용 시안은 아무의 일도 아니다.
- 제작자의 UX 완주 검증(§0 독자 2)도 실서식이어야 유효하다 — 중립 시안으로는
  실무 문서의 필드 밀도·문장 구조에서 나는 마찰을 재현하지 못한다.
- 도메인 결합의 실위험은 **소스 결합**(나라장터 API 류)이지 예제 문서의 소재가
  아니다. 예제는 문서 구조만 차용한 허구 데이터다(§2 허구화 규칙).

이 뒤집음은 #284 에 재판정 코멘트로 기록한다.

### D3. 행동 안내 = 진행 감지 체크리스트 (차단형 오버레이 기각)

접을 수 있는 패널에 단계 목록이 서고, 앱 상태가 조건을 만족하면 자동으로 체크되며
다음 걸음 한 줄을 안내한다. 코치마크(스포트라이트 투어)는 기각 — 실 UI 를 가리고,
화면 구조 변경마다 좌표 계약이 깨지는 유지비가 크다.

- **판정은 링1**: `gui/tutorial_state.py`(신설)가 단계 정의·달성 판정·안내 문안을
  소유한다. 링2 는 스냅샷을 그리기만 한다 — "같은 상태를 두 곳이 판정하지 않는다".
- **비차단·순서 비강제**: 사용자가 다른 길로 가도 막지 않는다. 단계는 달성 사실만
  체크한다(예: 데이터를 먼저 골라도 그 단계가 먼저 체크될 뿐이다).
- **명시 시작·명시 종료**: 예제 설치가 곧 튜토리얼 시작이고, 패널의 「튜토리얼
  닫기」로 언제든 끝낸다. 진행·해제 상태는 `settings.json` 에 영속한다(§4.4).

안내는 두 구성 요소다 — **체크리스트는 진행의 지도**이고, **순간 카드(moment
card)는 방금 지나온 걸음의 의미**다. 순간 카드는 단계가 달성된 직후 특정 요소를
짚지 않는 작은 카드가 떠서 방금 일어난 일(특히 *일어나지 않은 일* — 승인이 다시
서지 않음, 데이터를 다시 고르지 않음)의 의미를 말하고 자동 소멸한다. 행동 전
지시가 아니라 행동 후 의미 부여라서 "한 루프 최소 두 바퀴" 원칙(§3.1)과 맞물린다.
규칙: 클릭을 가로채지 않고, 확인 모달(`needs_confirm`)이 떠 있는 동안은 억제하며,
동시 1장·큐잉, 문안은 링1 소유, 놓쳐도 같은 문안이 체크리스트의 완료 단계
펼침에 남는다. 요소를 짚는 코치마크는 계속 기각이다 — 앵커 좌표가 DOM 계약의
소비자가 돼 화면 개편마다 드리프트하고, 사용자가 시키는 대로 누르기만 해
의미를 놓친다.

### D4. 제거 경로 = manifest 기반 일괄 제거 (#284 스케치 정정)

#284 스케치의 "「예제」 그룹 삭제 한 번으로 통째 제거"는 **현재 기제로 성립하지
않는다**. 그룹은 실체가 아니라 소속이라(`webapp/template_groups.py`),
`disband_group` 은 지정만 걷고 파일은 남으며, 파일 제거는 템플릿 1건 단위
`_do_delete`(.trash 이동) 뿐이고 되돌리기 슬롯도 최근 1건 전용이다.

대신: 설치가 **설치 manifest**(설치된 파일·풀 등록의 목록)를 남기고, 제거는
manifest 기재 항목만 일괄로 `.trash` 이동 + 그룹 해산 + 데이터 고정 해제한다.
제거 확인은 대상 N건을 재진술하고, **되돌리기는 재설치가 대신한다** — 자산이
번들에 있으므로 언제든 동일하게 다시 설치된다(벌크 undo 슬롯을 새로 만들지
않는다). 사용자가 예제 템플릿을 참조하는 작업을 만들어 뒀다면 제거 후 기존
템플릿 미존재 경보 표면이 그것을 정직하게 드러낸다.

## 2. 자산 명세

정본은 `examples/onboarding/`(가칭)의 생성 스크립트다 — quickstart-101 의
`make_template.py` 전례대로 스크립트에서 파생해 커밋하고, 손편집하지 않는다.
배포본에는 PyInstaller spec `datas` 로 동봉한다(§4.5).

### 2.1 허구화 규칙 (예외 없음)

원본은 실공문 2부(조달청 「낙찰자 선정 및 계약체결 안내」·「계약방법결정 및
구매추진 안내」)와 공고서 서식이다. 차용하는 것은 **문서 구조**(수신·제목·항목

공고/결의번호·연락처·주소·이메일·금액·일자. 실문서의 고유 식별 가능 값이 예제
자산·스크린샷·문안 어디에도 남지 않는 것이 게이트 조건이다(§6).

## 3. 루프 커리큘럼과 시나리오 대본

사용자 대면 이름(가안): **「예제로 시작하기」**, 티어 이름(가안): **기본·응용·
고급 + 선택 진입 심화**. 문안 확정은 구현 슬라이스에서
[화면 문안 스타일](COPY_STYLE_GUIDE.md)·[UI 용어 규약](UI_VOCABULARY.md)을 따른다.
어휘 주의 하나: 문서에서 넣고 뺄 수 있는 구간의 내부 명칭은 slot 이지만 사용자
어휘는 **「항목」**, 하나를 고르는 갈래는 **「선택」**이다 — 튜토리얼 문안에
슬롯·slot 을 노출하지 않는다(UI 용어 규약 정본).

### 3.1 원칙 — 난도는 기능이 아니라 루프 단위다

튜토리얼 난도는 화면·기능의 개수가 아니라 **의도된 사용자 루프를 몇 개, 몇 바퀴
도는가**로 자른다. 루프 목록은 기존 UX 설계 문서의 역참조로 세웠다(§3.2). 원칙 넷:

1. **한 루프는 최소 두 바퀴** — 한 번 지나간 경로는 절차 암기지 루프 체득이
   아니다. 기본 티어가 생성을 두 번 시키는 이유다(T8).
2. **티어 순서 = 문서가 선언한 반복 빈도 서열** — 일상 반복(제품의 심장)이 기본,
   세션 단위 루프가 응용, 1회성·최고 난도인 저작이 고급.
3. **부차 루프는 가르치지 않고 만나게 한다** — 제품 문서가 스스로 부차·격리로
   규정한 루프(판본 숫자·회복·정리·편집 거래)를 단계로 세우면 잘못된 비중을
   가르친다. 자연히 만나는 자리에서 문안 한 줄로만 짚는다.
4. **티어는 순차 제안·비강제** — 티어 완주 시 다음 티어를 제안하되 막지 않는다.
   티어 안에서도 단계는 달성 사실만 체크한다(§1 D3 승계).

| L8 템플릿 저작·컴파일 | `{{토큰}}` 서식 → 누름틀 컴파일 → L1 진입 | 1회성 — 빈도 최하·난도 최상 | UI 계약 S8-03(두 축: 필드 토큰 먼저·구간 표기 다음 — 순서가 계약) | 고급 |
| L8b 구간 구성 | 한 서식의 항목 구간을 넣고 빼고, 선택 갈래를 골라 변형 문서를 만든다 | 서식 도입 후 문서마다·가끔 | S6~S10 로드맵의 핵심 산출, UI 용어 규약(항목/선택), 「포함할 내용」 표면 | 심화(선택 진입) |

배치 판단의 부기 둘. ① L5(판본 숫자)는 「규칙이 갈릴 때만 오른다」가 계약이라,
전면에 세우면 제품이 부차라 선언한 것을 핵심으로 잘못 가르친다(옵션 왕복 재확정
결함 #877 은 U3 에서 해소됐다 — 심화 티어의 선택 전환이 이 수리 위에 선다).
② U3 의 반복 마찰 제거(#879 저장 폴더 기본값, #880
마지막 데이터 자동 마운트)는 이미 착지했다 — 두 번째 세션부터 T9 의 마운트가
자동일 수 있으므로, 체크리스트 판정은 "사용자가 골랐다"가 아니라 **마운트 성립
사실**로 세워 자동 마운트도 달성으로 친다.

### 3.3 기본 티어 「첫 문서」 (~15분) — L1 + L4a + L9(덮어쓰기)

| 단계 | 사용자 행동 | 달성 판정(체크리스트) |
|---|---|---|
| T0 예제 설치 | 빈 라이브러리의 「예제로 시작하기」 클릭 → 확인 | 설치 액션 성공(manifest 기록됨) |
| T1 템플릿 고르기 | ＋ 새 작업 → `계약체결안내` 「이 템플릿으로」 | 편집기 세션에 예제 템플릿 적용 |
| T2 매핑 확정 | 파일 선택 → `계약목록.csv` → 「모두 확정」 | 확정 7/7 도달 |
| T3 작업 저장 | 작업 이름·파일명 패턴 입력 → 「작업 저장」 | 작업 레지스트리에 저장 성립 |
| T4 데이터 겨누기 | 문서 만들기 → 데이터 선택(고정 목록에서) | 세션에 데이터 마운트 |
| T5 작업·행 선택 | 후보 카드 선택 + 「전체 선택」 | 현재 작업 성립 + 선택 ≥1 |
| T6 승인 | 생성 값 미리보기 → 「이 이름과 값으로 승인」 | pill 이 생성 준비로 전이 |
| T7 생성 | 「이 작업으로 문서 생성」 | 생성 완료 사건(성공 ≥1) |
| T8 **한 바퀴 더** | 같은 작업으로 다시 생성 → 덮어쓰기 확인 → 「덮어쓰고 생성」 | 같은 작업의 2번째 생성 완료 + 덮어쓰기 확인 사건 |

T8 이 기본 티어의 요체다 — 두 번째 바퀴에서 사용자는 ① 승인이 다시 서지 않음
(규칙축은 작업당 1회, L4a)과 ② 같은 이름 파일을 조용히 덮지 않음(L9)을 몸으로
확인한다. 설치가 하는 일은 종전과 같다: hwpx 3건 → 템플릿 「예제」 그룹, TXT
2건 → TXT 「예제」 그룹, CSV 2벌 → 홈 아래 예제 데이터 자리 + 「고정한 데이터」
풀 등록, 완료와 함께 체크리스트 패널 열림.

**티어 졸업 판정**: "이 작업으로 언제든 다시 만들 수 있다" — 정의 1회·생성 2회가
모두 성립.

### 3.4 응용 티어 「한 데이터, 여러 산출 — 그리고 새 데이터」 (~15분) — L2 + L6 + L3 + L4b + L9(결핍 2종)

| 단계 | 사용자 행동 | 달성 판정 |
|---|---|---|
| T9 작업 전환 | 마운트 유지한 채 `구매추진안내` 로 두 번째 작업 정의 → 생성 | 같은 마운트에서 2번째 작업의 생성 완료 |
| T10 TXT 작업 | `계약안내_기안` 으로 TXT 작업 저장 | TXT 작업 저장 성립 |
| T11 검토·복사 | 검토·복사 시작 → 「복사」 1건 이상(복사 후 다음 이동 토글) | 작업대 복사 카운터 ≥1 |
| T12 데이터 교체 | `계약목록_2.csv` 마운트 → 선택 0건에서 재시작 | 2번째 데이터 마운트 성립 |
| T13 빈 값 재승인 | 결측 행 포함 선택 → 본문 확인이 `납품기한` 지목 → 재승인 → 생성 | 빈 값 포함 승인 + 생성 완료(`〘미입력·납품기한〙` 표식) |
| T14 저작측 결핍 | `오류연습_보증금` TXT 작업 저장 시 비움 확정 게이트 통과 | 비움 확정 사건 발생 |

T9 의 문안이 L2 의 핵심을 짚는다 — "데이터를 다시 고르지 않았다. 데이터는
작업이 아니라 화면이 들고 있다." T12 는 반대로 교체 시 선택이 0건으로
재시작됨(앞 데이터의 선택을 새 행에 물려주지 않음)을 짚는다. T13·T14 는 결핍의
두 얼굴이다: 열은 있되 값이 빈 것(데이터측 → 실행마다 재승인)과 열 자체가 없는
것(저작측 → 저장 때 비움 확정). 한 데이터 위에서 HWPX 2종 + TXT 1종이 나오는
경험이 PATTERNS(102) 「한 데이터 → 3종 산출」의 이행이다.

**티어 졸업 판정**: "데이터가 바뀌어도, 산출이 여러 가지여도 리듬은 같다" —
한 마운트 위 작업 전환 1회·데이터 교체 1회·결핍 게이트 2종이 모두 성립.

### 3.5 고급 티어 「내 서식」 (~15분) — L8 → L1 재진입

| 단계 | 사용자 행동 | 달성 판정 |
|---|---|---|
| T15 누름틀 변환 | `공고서_연습` 행 ⋮ → 변환 확인 | compile 성립(`mutated` 통지) — 필드 토큰과 구간 표기 두 축을 함께 지난다 |
| T16 변환본으로 생성 | 변환된 템플릿으로 기본 티어 리듬 반복(작업→생성) | 해당 템플릿 생성 완료 사건 |

고급 티어가 튜토리얼의 진짜 목표다 — 예제 완주가 아니라 **자기 서식을 템플릿화할
수 있게 되는 것**. 기존 101 은 이것을 「다음 걸음」 표 한 줄로만 언급했다. T16 이
L8 의 출구가 L1 의 입구임을 몸으로 확인시키고, 마지막 안내 문안은 "이제 당신의
서식 파일을 「가져오기…」로 들여와 같은 변환을 하라"로 닫는다. slot 손질·
decompile 같은 저작 심화는 단계로 세우지 않는다 — decompile 은 「다시 변환
전까지 문서를 만들 수 없다」는 파괴적 전이라 튜토리얼이 유도할 자리가 아니다.

**티어 졸업 판정**: "당신의 서식을 가져와 같은 변환을 할 수 있다" — 변환 1회 +
변환본 생성 1회가 성립.

### 3.6 심화 티어 「구간 — 서식 여러 벌을 한 벌로」 (~10분, 선택 진입) — L8b

표준 완주는 고급까지다. 심화는 진입 동기를 가진 사용자만 위한 선택 티어로,
제안 문안이 그 동기를 짚는다 — *"거의 같은 서식이 여러 벌로 갈라져 있다면(계약
방법별·금액대별 공고서처럼), 구간이 그것을 한 벌로 만든다."* 원형인 공고서
샘플이 실제로 4벌(일반/제한 × 금액대)로 갈라져 있던 것이 이 티어의 존재 이유다.

| 단계 | 사용자 행동 | 달성 판정 |
|---|---|---|
| T17 항목 넣고 빼기 | T16 작업의 「포함할 내용」에서 항목 구간 하나를 빼고 재승인 → 생성, 앞선 산출과 비교 | 구간 구성이 다른 2번째 생성 완료 |
| T18 선택 고르기 | 선택 구간의 갈래를 바꿔 생성 | 다른 갈래로 생성 완료 |

T17 은 구성 변경이 규칙 변경이라 재승인이 다시 서는 것(L4a 의 두 번째 대면 —
기본 티어에서 배운 "조용해진다"의 예외가 아니라 정확히 그 규칙의 이행임을 순간
카드가 짚는다)까지 함께 가르친다. 갈래 왕복이 재확정을 무한 반복하던 결함(#877)
은 U3 에서 해소돼 이 티어가 그 수리 위에 선다.

**티어 졸업 판정**: "서식이 갈라질 이유가 구간으로 접힌다" — 항목 구성이 다른
생성 1회 + 다른 갈래 생성 1회가 성립.

## 4. 구현 좌표

접지 조사(2026-08-25, 이 문서 작성 시점 master)로 확인한 현재 표면 기준이다.

### 4.1 설치 진입점 — 두 빈 상태 + 상시 진입

- **library(문서 작업) 빈 상태**: `frontend/src/screens/library.ts` `LibraryList` 의
  `is_empty` 분기(판정은 링1 `home_state.py`)에 「예제로 시작하기」 버튼 추가.
  백엔드 동사는 `screen_library.py` 의 `_do_` 관례를 따른다.
- **편집기 템플릿 밴드 빈 상태**: `LibraryBand` 의 `emptyText` 는 문자열 prop 이라
  버튼을 품지 못한다 — 밴드 밖 공용 버튼 줄(`import-template` 등이 서는 자리)에
  상시 진입점을 두는 것이 기존 구조와 일치한다.
- job 랜딩 빈 상태는 건드리지 않는다 — 그 출구(「문서 작업」에서 고르기)가
  library 빈 상태로 이끌므로 거기서 만난다.

### 4.2 설치·제거 액션

설치·제거는 네이티브 파일 자원이 관여하므로 컨트롤러 액션으로 두되, 파일 복사·
manifest·풀 등록의 몸통은 external 층 신설 모듈(예: `external/example_pack.py`)이
소유한다. 그룹 지정은 기존 `TemplateGroupModel.set_group`, 데이터 고정은 기존
dataset pool 경로를 재사용한다 — 인라인 재구현 금지. frozen 자산 해석은
`web_artifact()` 와 같은 `sys.frozen`/`sys._MEIPASS` 분기가 유일한 전례다(범용
`resource_path()` 헬퍼는 없다).

### 4.3 체크리스트 — 판정·렌더·통신

- **링1** `gui/tutorial_state.py`: 단계 열거·달성 판정·다음 걸음 문안·직렬화
  스냅샷. 헤드리스 테스트가 전 단계 전이를 검증한다.
- **사건 주입**: 각 컨트롤러의 기존 전이 성립 지점(작업 저장, 마운트, 승인 전이,
  생성 완료, 복사 카운트, compile 성립 등)에서 튜토리얼 상태로 마일스톤을
  통지한다. 컨트롤러가 판정을 재구현하지 않는다 — 이미 성립한 전이 사실만
  넘긴다. 정확한 훅 지점은 구현 슬라이스가 확정한다.
- **렌더**: React 트리 셸 레벨(`react/boundary.ts` 의 형제 또는 ShellHost 내부)에
  패널을 세운다. `.topbar` 는 불가 — editor·workbench 몰입 표면에서 body 클래스가
  topbar 를 덮는다. 화면 전환은 `shellNav.subscribe()` 로 관측한다(패널이 `go()`
  성공을 낙관 가정하지 않는다 — 편집기 이탈 가드가 전환을 취소할 수 있다).
- **순간 카드**(§1 D3): 패널과 같은 셸 레벨·같은 마일스톤 사건·같은 스냅샷
  경로를 쓴다 — 별도 판정·통신 없음. 단계별 카드 문안은 링1 단계 정의의 필드다.
  요소 앵커를 두지 않으므로 DOM 좌표 계약이 생기지 않고, `prefers-reduced-motion`
  을 존중한다.
- **푸시**: 기존 `window.__hwpx` 스냅샷 사건에 얹는다. 새 통신 경로를 만들지
  않는다.

### 4.4 영속

`external/settings.py` 에 중첩 키 `tutorial`(진행 단계·해제 여부·설치 manifest
참조)을 `load_*`/`save_*` 짝 관례로 추가한다. 전례: `boot_completed_runtime`
(한 번만 일어나는 사실), `template_groups`(중첩 dict). localStorage 는 금지다(#74).

### 4.5 동봉과 게이트

- spec `datas` 에 예제 자산 튜플 추가(`packaging/hwpx_filler_web.spec`). 게이트:
  `packaging/verify_specs.py`, `tests/repo_contract/test_packaging_contract.py`.
- **live 게이트**: `scripts/live101/scenario.py` 에 `run_onboarding(ctx)` 최상위
  함수 추가 + `driver.py` phase 열거·디스패치·preflight 배선. 새 창 콜드 부팅을
  늘리지 않는 기존 규율에 따라 가능하면 기존 phase 의 창에 이어 붙인다.
- 커버리지: 새 서브패키지가 생기면 `docs/package_coverage_floors.toml` 하한 등록.

## 5. 기존 quickstart-101 과의 관계

두 세트는 독자가 다르다. `examples/quickstart-101/` 은 **저장소 독자**(개발자·
문서·live 게이트 회귀 기반)로 존속하고, 온보딩 세트는 **제품 독자**(exe 사용자)를
맡는다. 온보딩이 착지해도 101 을 걷지 않는다 — 101 의 발주 도메인 자산·스크린샷
재생성·live 게이트는 그대로 회귀 증거로 산다. 단, README 의 "설치본 사용자는

## 6. 슬라이스 분할과 성립 조건

구현은 이슈로 등록해 추적한다(이 문서는 TODO 를 갖지 않는다). 분할:

| 슬라이스 | 내용 | 선행 |
|---|---|---|
| A 자산 | `examples/onboarding/` 생성 스크립트 + 커밋 자산(§2) | — |
| B 동봉·설치 | spec datas + 빈 상태/상시 진입점 + 설치 액션·그룹·고정(§4.1–4.2) | A |
| C 제거 | manifest 일괄 제거 + 확인 재진술(§1 D4) | B |
| D 체크리스트 코어 | `tutorial_state.py`(티어·단계 = §3.3–3.6 정본, 순간 카드 문안 포함) + settings 영속 + 헤드리스 테스트(§4.3–4.4) | — |
| E 체크리스트 표면 | 셸 패널 + 마일스톤 배선 + 스냅샷 푸시(§4.3) | B, D |
| F live 게이트 | `run_onboarding` 실완주 + 드리프트 대조(§4.5) | B–E |

전체가 성립했다고 말할 조건:

- 빈 라이브러리 첫 화면에서 예제 설치 제안이 보이고, 누르기 전엔 홈에 아무것도
  쓰지 않는다(#284 완료 기준 승계).
- 설치된 예제만으로 전 티어 시나리오(생성 반복·작업 전환·데이터 교체·결핍
  게이트 2종·누름틀 변환·구간 구성)가 앱 안에서 완주된다 — 저장소·문서 없이.
- 제거 한 번으로 manifest 기재 자산이 전부 사라지고, 남는 실습 작업의 결핍은
  기존 경보 표면이 정직하게 드러낸다.
- 체크리스트의 모든 단계 판정이 링1 헤드리스 테스트로 검증되고, live 게이트가
  같은 여정을 실창에서 완주한다.
- 예제 자산·문안·스크린샷 어디에도 원형 실문서의 식별 가능 값이 없다(§2.1).
- 설치형·포터블·소스 실행이 동일하게 동작한다.
