# 작업 편집

## 입력과 저장

편집기는 템플릿과 데이터를 조합해 재사용할 작업을 만든다. 템플릿 풀과 데이터 풀은
같은 고르기 단계에서 사용하며, 조회 목록을 편집기가 별도 원장으로 복제하지 않는다.
등록 데이터는 표시 이름이 아니라 안정된 `key`로 고른다.

저장된 작업은 템플릿, 필드 연결, 파일명 규칙과 데이터 참조를 가진다. 데이터의 행 내용은
저장하지 않는다. 데이터 결속을 쓰는 공개 경계는 **편집기 저장 하나**다.
경로·시트·헤더 행·종류를 한 벌로 포획하며, 열린 편집 세션을 변경 가능한 풀 key에
계속 매달지 않는다. 입력을 고르지 않은 세션에 저장 가능한 것처럼 보이는 우회 동선을 만들지 않는다.

## 연결 확인

연결 표는 필드, 데이터 열, 표시형, 미리보기의 네 축으로 읽는다. 필드당 데이터 열은 하나다.
유형은 텍스트·날짜·금액·고정값·오늘 날짜이며, 고정값과 오늘 날짜는 데이터 열을 읽지 않는다.
오늘 날짜의 값은 실행 시각을 사용한다. 이름이나 표본에 의한 자동 연결은 **제안**일 뿐이다.

사용자가 제안을 확인하거나 의도적 비움을 선언해야 한다. 일괄 확인은 자동 제안의 승격이지
모든 미연결 필드를 비우는 승인이 아니다. 유형과 표시형은 `set_display`의 한 전이로 변경해
중간의 무효 조합을 노출하지 않는다. 리터럴 고정값, 표시형, 열 선택의 판정은 backend가 한다.

미리보기는 실제 선택 데이터의 값을 사용한다. 누락 표식은 생성에 사용하는 도메인 값을
그대로 투영하고 웹이 별도 문자열을 합성하지 않는다. 사람이 의도한 비움과 데이터에 값이
없는 경우, 데이터 열 자체가 없는 경우를 섞지 않는다. [용어 규약](../UI_VOCABULARY.md)을 따른다.

## 편집 전이

탭 이동과 이탈은 세션의 patch 정책을 통과한다. `discard_patch`에 section이 있으면 그
부분만, 없으면 세션 전체의 되돌리기 경계다. 화면이 자체적인 저장·버리기 결과를 먼저 선언해
컨트롤러 판정을 건너뛰지 않는다. 이름 충돌은 저장 시 정확한 덮어쓰기 확인으로 다룬다.

저장 후 실행 진입도 현재 데이터 결속을 확인하는 공용 진입 명령을 사용한다. 웹이
`select_job`만 호출하거나 기억한 경로로 컨텍스트를 복원하는 지름길은 금지한다.

## 템플릿 저작과 확인

HWPX 누름틀 변환·lint·스키마·구간 표기 처리는 제품/커널의 결과를 사용한다. 변환은
명시적인 사용자 행동이며 원본 템플릿 변경과 산출물 생성을 혼동하지 않는다.
템플릿 폴더 안의 작업과 외부 경로의 세션 작업은 구분한다. 루트 판정은
[라이브러리와 저장](storage.md)의 규칙을 따른다.

TXT 편집기의 CodeMirror는 등록된 vendor 소유자를 통해 설치·갱신·해제한다.
프런트 다른 모듈에서 vendor 객체나 타입을 직접 소비하지 않는다.
