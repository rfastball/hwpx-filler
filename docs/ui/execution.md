# 실행과 결과

## 작업과 데이터의 결속

`Job`은 데이터 경로·시트·헤더 행·종류에 지속적으로 결속된다. 작업을 고르면 그 데이터가
서고, 데이터를 고르면 그 데이터에 결속된 작업만 후보가 된다. 스키마 호환성은 후보 관계의
대체 기준이 아니다. 결속된 데이터에서 필요한 열이 사라졌는지 검사하는 실행 게이트다.

데이터만 먼저 열 수 있지만 후보의 첫 항목을 자동 선택하지 않는다. 마운트 직후 행 선택은
0건이다. 같은 데이터의 다른 작업으로 옮길 때 불필요한 재읽기와 선택·필터 초기화를 피한다.
다른 데이터를 열어 결속이 어긋나면 작업을 해제한다. 결속 정보가 없으면 편집기로 연결한다.

| 소유자 | 책임 |
|---|---|
| `JobDataSession` | 마운트 데이터, 선택, 필터, 범위 |
| `ActiveWorkSession` | 작업 identity, 후보, 재읽기, 재연결, 탐색 |
| `JobExecutionSession` | 구성, 봉인, 관찰, 준비 |
| `DocumentRunCoordinator` | 실행 잠금, 취소, 입력 고정, 덮어쓰기, 결과, 배달 |
| `JobController` | 위 책임들의 브리지 조정 |

snapshot은 준비된 view를 순수하게 성형한다. IO 갱신은 `refresh_panel()` 같은 명시적
경계에서 한다. 브리지는 `mounted_data_descriptor`와 `owned_session_paths`를 통해 필요한
데이터 설명과 경로만 읽는다. 편집기 handoff도 포획된 참조를 넘기며 풀을 다시 조회하지 않는다.

## 선택·필터·범위

검색·열 필터·행 선택·전문 범위 초안은 같은 데이터 세션을 대상으로 한다. 늦게 도착한
변이가 다른 데이터나 닫힌 초안에 적용되지 않도록 epoch를 대조한다. 보기에서 열을 숨겨도
그 열은 필터·검색·생성 입력에서 사라지지 않는다.

실행 입력은 선택된 행을 **표시순서로 투영한 고정 사본**이다. 선택 index만 뒤늦게 해석하거나
화면 표시순서와 원본 순서를 섞지 않는다. 작업대도 이 사본을 받아 사용한다.

## 포함할 내용과 템플릿 변경

「포함할 내용」의 노출 여부, 선택 필요 상태, 프리셋 호환성은 Python의 projection이 소유한다.
복구 동사가 필요한 blocker가 있으면 그 동사에 도달할 수 있어야 한다. 오류·거절 결과는
정상 구획을 숨기는 술어 때문에 사라지지 않는다.

프리셋 목록에는 현재 구조에 전부 적용 가능한 항목을 보여준다. 손상 항목은 삭제하거나
숨기지 않고 이유와 함께 표시한다. 저장과 적용은 별도 동사이며 자동 적용하지 않는다.
이름 충돌 확인은 backend가 반환한 기존 항목의 key로 되돌려 보내고, 적용 후 새 view와
token으로 교체한다. 적용된 수치·깨진 선택 수치는 웹에서 다시 세지 않는다.

템플릿 변경 구획은 원본 변경·미종결 준비·초기화 문제 등 **조치가 있을 때** 보인다.
읽지 못한 원본은 「변경 없음」이 아니다. 창 포커스 복귀의 새로고침은 편의 기능이며 안전
게이트를 대신하지 않는다. 실행 직전에도 원본 드리프트와 준비 상태를 검사한다.
최초 준비는 명령 경계에서 수행한다. snapshot 조회만으로 durable identity를 만들지 않는다.

## 생성과 덮어쓰기

생성은 현재 입력·구성·준비를 확인하고 실행 계획을 봉인한 뒤 materialization과 배달로
진행한다. 과거의 준비 결과나 UI의 활성 버튼을 현재 실행 허가로 쓰지 않는다.
구성 변경·프리셋 적용·경로 변경과 생성의 상호배제를 backend에서 보장한다.

현재 HWPX 흐름에는 생성 직전 별도 「생성 값 미리보기」 승인 시트가 없다. 연결 확인과 실행
게이트가 입력을 검증하며, 생성 뒤 실제 결과를 관찰한다. 기존 파일을 덮는 경우에는
`generate`의 `needs_overwrite` 확인 왕복을 거친다. 확인한 대상과 실행할 대상이 달라졌으면
이전 승인을 재사용하지 않는다. 저장 폴더 결정은 [저장 규칙](storage.md)이 소유한다.

## 산출물 관찰

「내용 보기」는 배달된 파일을 다시 읽고 기록된 digest와 비교한 뒤 재파싱한다.
세션의 ordinal로 대상을 특정하며 파일명·표시 index를 권위로 쓰지 않는다.
파일 없음, digest 불일치, 재파싱 실패, 세션 밖 대상은 각각 명시적인 실패다.

관찰은 문단 텍스트·표·병합 메타·누락 표식의 구조 보기다. 한글의 페이지 조판을 재현하는
미리보기가 아니다. 표시하지 못한 구간의 존재와 이유도 보여 주며, 전체 관찰인 척하지 않는다.
다른 이름으로 저장할 때는 검증해 관찰한 bytes를 저장한다. 새로 생성한 bytes로 바꾸지 않는다.

이전 실행 결과는 입력이 바뀌면 현재 입력의 성공 증거가 아니다. 결과의 현재성·과거 상태와
실패·취소·배달 결과를 별도로 표시한다. 일부 문서가 만들어진 실패를 통째 성공이나 전부 실패로
뭉개지 않는다.

## TXT 검토·복사

작업대는 진입 때 받은 고정 사본의 내용을 한 건씩 검토·복사한다. 작업 화면의 이후 선택
변경을 실시간으로 따라가지 않는다. 클립보드 실패와 복사 진행 상태를 구분하고,
빈 값 표식을 실제 빈칸으로 지우지 않는다. 작업대의 편집·진행과 durable 작업 정의는 별개다.
