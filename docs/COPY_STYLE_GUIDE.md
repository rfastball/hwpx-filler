# 화면 문안 스타일

이 문서는 사용자 대면 문장의 형식과 예산을 소유한다. 명칭·비어 있음·단위는
[UI 용어](UI_VOCABULARY.md)가 소유한다. 같은 용어표를 여기 다시 관리하지 않는다.

## 1. 대원칙

문안은 무엇이 안 됐는지와 다음 행동을 말한다. 정상 경로는 기본적으로 무음이다.
화면이 이미 보여 주는 결과, 시스템의 설계 이유, 하지 않은 일의 나열을 설명하지 않는다.
「묻고 확정하거나 시끄럽게 알린다」는 실패·불확실성·손실에 대한 규칙이지 정상 완료를
낭독하라는 뜻이 아니다. 파괴 확인의 손실 집합은 생략하지 않는다.

## 2. 문형별 예산

| 문형 | 형식 |
|---|---|
| 버튼·메뉴 | 행동이 분명한 명사구·동사구 |
| 상시 힌트·부제 | 기본 0; 빈 상태에서 다음 행동이 필요하면 한 문장 |
| placeholder | 입력 예나 이름 한 구 |
| 툴팁 | 한 문장; `이름: 설명` |
| 상태·수치 | 라벨 중심; 화면 결과와 중복되는 정상 완료 문장은 없음 |
| 오류 | 최대 두 문장: 문제, 조치 |
| 파괴 확인 | 제목=행동, 본문=결과·손실 목록, 확인 버튼=그 행동 |

## 3. 표기

문장 안 em dash와 낫표는 쓰지 않는다. 절을 없애거나 마침표·쉼표·작은따옴표로 바꾼다.
테이블의 빈 칸을 나타내는 단독 `—`는 문장이 아니므로 허용한다.
명령형은 `~하세요`로 통일한다. 취소 버튼은 `취소`, 파괴 버튼은 `삭제`·`덮어쓰고 생성`처럼
구체적 동사를 쓴다. 파괴 확인의 기본 포커스는 취소다.

## 4. 용어와 데이터 표식

「결속하다·물리다·겨누다」는 사용자에게 「연결하다」로 풀어 쓴다.
미입력·빈칸·미매칭을 사용자 설명 문장에서 임의로 혼용하지 않는다.
본문의 누락 표식은 UI 문구가 아니므로 [용어 규약](UI_VOCABULARY.md)의 예외를 따른다.

## 5. 예시

`이 파일에는 시트가 여러 개 있습니다. 사용할 시트를 선택하세요.`는 선택이 필요한 이유와
행동을 말한다. 「조용히 첫 시트를 쓰지 않습니다」 같은 설계 원칙 낭독은 덧붙이지 않는다.
`연결된 파일을 찾을 수 없습니다. 데이터 파일을 다시 선택하세요.`처럼 오류와 조치를 나눈다.
이 예시가 코드의 실제 문자열을 별도 소유하는 것은 아니다.

## 6. 파괴 확인

손실은 `사라지는 것: 선택 3행 · 필터 2조건`처럼 구체적 집합으로 쓴다.
단순히 「계속하시겠습니까?」라고 묻고 실제 손실을 숨기지 않는다.

## 7. 변경 범위

문안 정리로 코드 식별자·JSON 키·판정 로직을 바꾸지 않는다. 코드 주석과 docstring의 문체는
사용자 문안 규칙 밖이다. 문자열 변경은 문안 assertion과 census를 같은 변경으로 갱신한다.

## 8. census 게이트

[ui_copy_census.toml](ui_copy_census.toml)은 실 소스의 문장 allowlist다.
[스캐너](../scripts/ui_copy_census.py)와
[계약 테스트](../tests/repo_contract/test_ui_copy_census.py)가 다중집합으로 대조한다.
새 문장은 기본 0이다. 필요한 새 문장은 PR에 이유를 쓰고 등록하며, 지운 문장은 함께 제거한다.
재생성 명령은 `uv run python scripts/ui_copy_census.py --write`다.

`해야 …할 수 있습니다`, 정상 완료의 `불러왔습니다·가져왔습니다·복원했습니다`, 문장 뒤
수치 나열, `실제 …입니다`, 현재 화면·모드의 낭독은 금지 패턴이다.
`legacy = true`는 기존 유예 문장에만 쓴다. 새 문장의 우회 수단이 아니며 총수는 늘지 않는다.
패턴의 실행 정의는 스캐너의 `NARRATION_PATTERNS`를 대조한다.
