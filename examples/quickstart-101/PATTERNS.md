# 문서나르미 102 — 세 가지 실전 조합 (GUI)

[README](README.md) 의 101(작업 하나 만들어 문서 생성)을 뗐다면, 실무는 대개 이 셋이다.
전부 화면에서, 같은 `quickstart-101/` 자산만으로 재현된다. 먼저 **[`start-101.cmd`](start-101.cmd)
를 더블클릭**해 앱을 띄운다(101 준비 참고 — 런처가 이 폴더를 홈으로 잡아 준다).

1. **한 데이터 → 여러 템플릿** — 한 벌 데이터로 여러 문서를 한 번에.
2. **여러 데이터 → 한 템플릿** — 여러 배치(부서·월별 파일)를 한 템플릿으로.
3. **저장된 작업(Job) 간 전환** — 반복 업무를 골라 쓰기.

먼저 **작업 두 개**를 만들어 둔다(101 의 "① 작업 만들기"를 두 번). 아래 셋이 이 둘을 쓴다.

- 작업 `발주요청서` — 템플릿 `templates/발주요청서.hwpx`, 파일명 `발주요청서-{{공고번호}}`.
- 작업 `구매요청서` — 템플릿 `templates/구매요청서.hwpx`, 파일명 `구매요청서-{{공고번호}}`.
  (「필드 연결·표시」에서 같은 `data/발주목록.csv` 를 고르면 4필드가 똑같이 자동 제안된다.)

> 팁: **템플릿 관리** 화면에도 이 폴더의 두 템플릿이 떠 있다 — 누름틀까지 컴파일된 카드에는
> **[작업 만들기]** 가 붙어, 그 템플릿이 채워진 편집 모드로 바로 들어갈 수 있다.

**세 조합 모두 순서가 같다: 데이터를 먼저 올리고, 그 데이터로 쓸 작업을 고른다.**
작업은 데이터를 기억하지 않으므로(README 「저장은 데이터를 등록하지도, 이 작업에 묶지도
않는다」) "어느 데이터로 만드는가"는 언제나 그 자리에서 사람이 정한다.

---

## 1. 한 데이터 → 여러 템플릿

**데이터를 한 번만 올리고, 그 위에서 작업만 갈아 끼운다.**

1. **문서 만들기** 탭에서 **[데이터 선택…]** → **[파일 찾아보기…]** 로 `data/발주목록.csv`
   를 고르고 **[닫기]**. 오른쪽 *이 데이터에 사용할 문서* 에 두 작업이 후보 카드로 선다.
2. `발주요청서` 카드를 고른다 → 왼쪽 표에서 **[전체 선택]**(3건) → **[생성 값 미리보기]**
   에서 **[이 이름과 값으로 승인]** → **[이 작업으로 문서 생성]**. (3건)
3. **후보 카드에서 `구매요청서` 로 갈아탄다.** 데이터도, 방금 고른 3건도 그대로 살아
   있다 — 전환이 버리는 것은 **실행 증거**(앞 실행의 결과 표시와 승인)뿐이다. 그래서
   상태 pill 은 다시 **승인 필요**로 선다. 처음 만든 작업이라서가 아니라 **전환이 승인을
   버리기 때문**이고, `발주요청서` 로 되돌아와도 마찬가지다 — 어느 규칙으로 무엇을
   만드는지는 만들기 직전에 다시 확인받는다. **[생성 값 미리보기]** →
   **[이 이름과 값으로 승인]** → **[이 작업으로 문서 생성]**. (3건)

기본 저장 폴더(`templates\Results`)에 여섯 개가 나란히 생긴다 — 파일명 앞머리가
달라(`발주요청서-…` / `구매요청서-…`) 겹치지 않는다.

**부분집합 템플릿은 필요한 필드만 쓴다.** `구매요청서` 는 4필드(수요기관·공고명·추정가격·
담당자)만 채우므로 데이터의 남는 열은 그냥 안 들어간다 — 값이 사라진 게 아니라 이
템플릿이 안 쓸 뿐이다.

> 텍스트 초안까지 한 벌에 넣고 싶으면, HWPX 는 위처럼 일괄 생성하고 기안문은 **TXT 작업**
> 을 하나 저장해 두고 같은 데이터 위에서 후보 카드로 골라 **검토·복사 작업대**에서 뽑는다
> (README 트랙 B). 「한 데이터 → 3종 산출」이 한 데이터 마운트 위에서 끝난다.

## 2. 여러 데이터 → 한 템플릿

작업 하나(`발주요청서`)에 **데이터만 바꿔 다시 생성**한다. 같은 저장 폴더로 내면
결과가 **누적**된다. (부서별·월별로 파일이 쪼개져 오는 실무에 맞는다.)

1. `data/발주목록.csv` 를 올린 상태에서 `발주요청서` 후보 카드 → 행 선택 → 승인 →
   **[이 작업으로 문서 생성]**. (3건)
2. **현재 데이터**의 **[데이터 선택…]** → 「다른 데이터」의 **[파일 찾아보기…]** 로
   `data/발주목록_2.csv` 로 바꾼다. 고르고 나도 **창은 닫히지 않는다** — 「이 데이터 고정」
   이라는 결정이 아직 남아 있어서다(고정 목록에서 고르면 남은 결정이 없어 즉시 닫힌다).
   이대로 쓸 것이면 **[닫기]**. **새 데이터를 올리면 선택은 0건에서 다시 시작한다** —
   앞 데이터의 선택을 새 행에 조용히 물려주지 않는다. **[전체 선택]**(2건) →
   **[이 작업으로 문서 생성]**. (**같은 저장 폴더**)

저장 폴더에 3 + 2 = 5개가 누적된다(`…-001~003` 다음 `…-101, …-102`).

**같은 파일명이 겹치면 두 번째 생성에서 "덮어쓰기 확인"이 뜬다.** 두 배치의
`공고번호` 가 겹쳐 파일명이 같아지면, 앞서 만든(손보정했을 수 있는) 산출물을 말없이
덮지 않으려고 대화상자가 총량·덮을 건수·새로 만들 건수를 세어 보여 준다. 정말 교체할
거면 **[덮어쓰고 생성]**. (이 예제는 번호가 안 겹쳐 그냥 누적된다.)

> **자주 쓰는 데이터라면 고정해 둔다.** **[데이터 선택…]** 창에서 지금 쓰는 파일 옆의
> **[이 데이터 고정…]** 을 누르면 그 파일이 「고정한 데이터」에 남아, 다음부터 파일 찾기
> 없이 한 번에 고를 수 있다(경로만 저장하고 생성 때 다시 읽는다 — 스냅샷 아님).
> 고정은 **데이터를 고르는 자리에서만** 일어난다 — 작업을 저장한다고 그 데이터가 함께
> 등록되거나 그 작업에 묶이지는 않는다.

## 3. 저장된 작업(Job) 간 전환

앞의 것들이 보여주듯, 한 번 저장한 작업은 템플릿·매핑·파일명을 **기억**한다. 매번 다시
설정하지 않고 **골라 쓰는** 게 핵심이다. 전환하는 자리는 둘이고 쓰임이 다르다.

- **데이터를 이미 올려 둔 채 바꿀 때** — 「문서 만들기」 오른쪽 후보 카드(또는 그 아래
  **문서 탐색 면**의 「사용 가능」 행). 데이터·선택·필터는 세션 소유라 **전환에서 살아남고**,
  버려지는 것은 **실행 증거**(앞 실행의 결과 표시와 승인)다. 승인이 함께 버려지는 것은
  고장이 아니라 계약이다 — 살아남은 선택 위에서 규칙만 갈아 끼운 채 확인 없이 만드는
  길을 두지 않는다. 지금 무엇이 열려 있는지는 후보 카드의 강조와 하단 액션바에 적힌
  작업 이름이 말한다.
- **작업을 찾거나 정리할 때** — **문서 작업** 탭. 행을 고르면 오른쪽에 상세가 열리고,
  아래 고정된 **[문서 만들기에서 사용]** 이 그 작업을 열어 준다.

**확인이 필요한 작업은 숨기지 않는다.** 템플릿이 사라진 작업 등은 탐색 면의 「확인 필요」
탭에 **비활성 + 막힌 이유 병기**로 선다 — 목록에서 지워 놓고 나중에 놀라게 하지 않는다.

**내용 바꾸기·지우기** — **문서 작업** 탭에서 행을 고르면 상세 아래에 상시 버튼이 선다
(스크롤과 무관하게 고정):

- **[작업 편집]** → 저장된 값이 채워진 편집기(템플릿·매핑·파일명 수정 후 **[작업 저장]**).
- **[이름 변경]** · **[그룹 이동]** · **[태그…]** · **[복제]**.
- **[삭제]** → **묻지 않고 바로 지운다.** 대신 지운 직후 10초 동안 **되돌리기**가 뜨고
  파일은 백엔드 `.trash` 에 30일 남는다 — 사후 관용이 있으니 사전 확인으로 매번
  가로막지 않는다. **예외는 하나다**: 그 작업이 「문서 만들기」에 진행 중인 세션으로
  열려 있으면 그때만 확인을 묻는다. 세션의 선택·진행은 파일을 복원해도 돌아오지 않아
  되돌리기가 못 갚는 소실이기 때문이고, 확인 문안이 그 사실을 먼저 말한다.

**저장된 작업의 실제 모습.** 작업은 `jobs/발주요청서.job.json`(이 폴더 밑, 홈 지정 덕에)
으로 남는다. 열어 보면 `{템플릿 + 매핑 + 파일명}` + 약간의 메타뿐 — **데이터·행은 없다.**

```json
{
  "version": 1,
  "name": "발주요청서",
  "template_path": ".../templates/발주요청서.hwpx",
  "filename_pattern": "발주요청서-{{공고번호}}",
  "mapping": { "name": "발주요청서", "mappings": [ /* 필드↔소스 */ ] }
}
```
